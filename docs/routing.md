## 1. 适用范围与两种身份

规则只作用于已经进入 Hoopa 入口的连接，不接管整机网络。不默认启用 TUN、系统代理、特权模式，也不修改父 shell。direct/inherit、NO_PROXY 和应用自身绕过代理的连接不会因配置了进程名而被自动捕获。

| 匹配维度 | 身份与边界 |
| --- | --- |
| 应用 profile | Hoopa 声明的 app ID，通过 launch 和可识别的专属入站绑定；不等于程序文件名或可信 OS 安全身份 |
| 源进程实例 | 原始 TCP connect 发起进程（connector）的 PID + OS 启动实例；不能把可复用 PID 当作长期配置 |
| 进程名/路径 | 对 connector 建连时名称/可执行路径快照作精确匹配；各字段须有已验证能力，用户/命名空间等条件在可验证时支持 |

同一规则内的多个条件取 AND；规则之间按显式顺序判断。进程名相同但路径不同可以分别配置，不能因统计视图选择同名合并而合并路由身份。正则/通配、签名身份和进程树继承不作为首期默认能力，避免从模糊名称推导过宽匹配。

名称/路径规则必须绑定字段来源和定义版本。[ADR010](adr/010-restricted-identity-profile.md)确定受限 Linux 候选按同次 executable 路径的 basename 匹配程序名；kernel comm 规则需要另一项已验证能力，应用显示名也不能代替程序名。固定0017候选已按显式 profile 验证精确名称/路径与三值规则，适用范围见[来源身份验收](validation/source5-formal-identity.md)；stock核心、未声明该能力的配置和未验证平台仍不获此支持。旧 v3/v4 契约不自动升级，下方示例中的 `name`/`executable` 仍为待定产品 schema，不能直接当作现有配置。

P1 应用规则通过入站上下文生效，不要求读取原始进程 PID；P2 进程规则采用 `basis=connect_initiator_v1`，需要原始 connect 证据及其与 accepted socket 的关联。子进程自己 connect 归子，父 connect 后子写归父 connector；FD 转交、fork 共享和后续写入者变化不改写该连接身份。GOST、launcher 或 profile 不能替代 connector；父进程若确实 connect，须有真实证据，不能凭进程树推断。解释与 JSON 显示建连快照、观测时点及共享转交限制；未监测 FD 转交时明确 `fd_transfer_observation=unverified`。此口径不表示逐字节 writer。

## 2. 规则顺序与目标

应用、进程、域名、IP 等条件进入同一份有序本地策略，从上到下取第一条确定匹配的规则。不存在隐式的“应用总比域名优先”或“更具体自动优先”。需要优先保留内网直连、阻断或域名例外时，将相应显式规则放在前面，plan 展示最终顺序与遮蔽关系。

目标支持稳定逻辑 group 或固定节点：

- **group**：推荐日常使用 US / JP / BEST 等本地组，节点变化通过组管理；自动组仍只能在明确候选内选择。
- **node**：使用订阅/provider ID 与稳定 node ID 引用，展示名仅用于 UI，避免同名、改名或供应商切换后误选。

固定 provider + node ID 是显式 pin，不随 active_subscription 切换重绑定；逻辑组继续按各自的跟随策略解析。编译完整候选时同时校验活动组与所有显式 pin 引用的来源快照，即使某 pin 的 provider 不是当前活动订阅，也只能使用它被明确引用的固定节点，不成为其他组的后备候选。引用失效时拒绝变更，不能改指活动订阅中的同名节点。

示例仅说明候选 schema，不是当前可用配置；最终字段随版本化 schema 定稿：

```yaml
routing:
  rules:
    - id: git-jp
      match:
        process:
          name: git
          executable: /usr/bin/git
      target:
        group: JP
    - id: agent-us
      match:
        app: agent
      target:
        group: US
    - id: downloader-fixed
      match:
        app: downloader
      target:
        node:
          provider: primary
          node_id: node-opaque-id
```

示例中，agent profile 的 git 子进程若能被证明匹配第一条，则走 JP；否则该 profile 的其他已判定连接按顺序匹配 US。把 agent-us 放到前面会遮蔽后续相关进程规则，必须在预览中说明，不能静默重排。

运行时按 `match / no_match / identity_unavailable` 三态处理。遇到一条可能匹配但所需源身份不可证明的规则，拒绝该连接并给出可查询的身份缺失原因；不能将 unknown 当作 no_match，悄悄继续到默认直连或其他供应商。已在更早规则确定匹配的连接不需要评估后面的进程条件。

## 3. P1 应用入站编译候选

无应用定向规则的不计量应用可沿用共享入口。需要应用上下文时，为 profile/launch 生成命名且可识别的 Mihomo HTTP/mixed 入站，launch 将目标子进程代理变量指向它；计量关闭也能使用该路径，不依赖 GOST 或账本。

完整计量候选直接进入具备已验证事件能力的 Mihomo 应用入站，保留原始 socket、应用上下文、计数与实际链；GOST 仅作兼容和累计对照，不能成为完整计量必经转发层。专属端口及可用认证用于上下文隔离，不能据此宣称同用户进程之间已有安全隔离。

Mihomo 的 named listener、IN-NAME/IN-PORT、sub-rule 是可供验证的编译构件。优先使用能保留统一规则顺序的命名入站匹配；多种规则组合须与 Hoopa 的顺序语义一致。listener 的 proxy 字段可直接指定节点/组，但可能绕开常规规则；首期不把它作为无需校验的快捷实现，以免丢失前置域名例外或阻断规则。

P0 必须证明固定核心版本支持所需 listener、规则组合及无 GOST 路径，并验证多个 profile 并发、端口冲突、认证、入口标识与实际节点。不满足时调整编译方案，不能把 P1 应用规则重新标为“仅将来探索”。

## 4. P2 原始进程匹配门槛

Mihomo 的 PROCESS-NAME/PATH/UID 等规则可以提供原生构件，但不能自动覆盖 GOST 转发后的原进程身份。原生查找模式、权限、平台差异与查询失败行为须固定版本验证；不能假设上游默认失败策略满足 Hoopa 的三态拒绝要求。

P0 比较原始入口归属和可保留身份的路由适配：connector 的建连实例及所需名称/路径快照必须在该次路由选择前可用，并验证快照与原 accepted socket 属于同一连接；不能等历史采集补到 PID 后才声称当时按该 PID 路由。晚到证据可修正统计，但不能倒写历史路由决策。已验证 connector 不因 socket 共享/转交自动变 unknown；connector 不明、事件丢失、后端 generation 不符或关联多解时保持未知，规则所需字段 unknown 按三态拒绝，不降为 no_match。

规则执行依赖已应用到转发层的策略，不能逐连接依赖管理器在线 RPC，破坏管理器崩溃后转发继续的要求。现有组合如果不能同时满足原身份、规则顺序、失败关闭和进程独立存活，应由主代理调整适配设计；不预先宣称原生进程规则已通过。

进程规则未具备已验证能力时，不接受含该条件的活动配置，plan 返回 `process_routing_unavailable`；名称与路径能力分别校验，任一所需能力未支持即在加载时拒绝，不能以已支持 name 推定 path 可用，也不能用一个永远拒绝的规则冒充功能完成。只使用已验证应用/域名规则的不计量基础路径可继续交付。

## 5. 变更、失效与运行连接

编译前验证所有 group、节点、订阅来源、匹配能力与入站引用。必需组为空、固定节点被删除、身份规则不受支持或引用失效时拒绝本次变更，保留上一份完整可用快照；不换供应商、换地区或静默直连。

固定节点运行时不可达时报告连接失败，不自动改选其他节点。group 的手动/自动策略按显式配置执行；节点重新变健康不代表已有连接会迁移。用户选择其他来源或解除固定须形成可见的规则变更。

plan 列出规则顺序、受影响 app/进程、目标、遮蔽和不确定条件、所需入站、端口变化、连接中断与回滚世代。配置提交复用现有快照、操作记录和恢复流程，不另建一套路由写入路径。

新增或修改规则主要影响新建连接；连接池、keep-alive、后台进程或加密复用连接可能继续原路径。首期需要受控重启的变更明确说明中断；不承诺给已建立 socket 换节点。逻辑组改变后，质量视图保留连接实际链，不用 group 当前选择覆盖历史。

路由解释分开列出本地规则意图、当时判定的身份与目标、连接实际观测的节点/链和证据时间；未知实际链不能用配置推导填满。查询不进行主动联网、恢复或改选。候选命令名和示例不作为已实现 CLI 接口。
