# ADR 012：P1 持久文件存储与发布边界

日期：2026-10-27。决定：采用 Linux 私有文件存储，基础管理不引入数据库。
实现及限定验证见[文件存储验收](../validation/p1-file-store.md)；产品生命周期仍由 T034 验收。

## 背景与选择

P1 需要保存完整快照、active 指针和后续操作/运行记录。runtime 目录可能在注销后
被清空，因此不能作为持久状态的权威，也不能把唯一的持久写入者锁放在那里。
采用 state 内持久 `.writer.lock` 的非阻塞 flock，进程退出由内核释放持有；正常关闭
不删除锁文件。runtime 保留 socket 和临时资源。此决定细化旧设计中“锁/socket 放
runtime”的泛称，不改变核心进程的复合身份和独立运行原则。

不采用 SQLite 保存基础管理状态，避免计量故障阻止代理管理；也不以多个 JSON
文件的 rename 宣称共同事务。文件发布、运行态修改、操作终态仍是三个独立边界。
具体格式、路径、上限和权限见[文件存储 v1 契约](../../specs/001-hoopa-proxy-manager/contracts/file-store-v1.md)。

## 不变量与失败处理

- 只读打开不建目录、锁或默认指针；已有状态缺 active 指针时拒绝初始化。打开存储
  不启动/认领/停止核心，也不补记任何操作终态。
- bundle 包含完整文件清单、大小和 SHA-256，并保留 generation、编译器、固定
  二进制引用及能力摘要。存储完整性不替代配置语义、二进制身份或能力验证。
- bundle 的独占临时目录与目标目录同属 bundles：每个文件及 manifest 同步/关闭，
  临时目录同步，发布 generation 名称，最后同步 bundles。既有 generation 只能在
  全部内容一致时幂等接受，损坏或差异拒绝。
- active 在 state 内以独占临时文件写入、同步、关闭、rename，再同步 state；只能
  引用完整 bundle。revision、配置 generation、进程 RunID、CounterEpoch 各有独立含义。
- rename 或发布后的目录同步不确定时，当前 writer 进入禁止后续写入的状态，读操作
  仍可观察文件。关闭后显式 writer 重开会重新同步 state 和持久子目录，再由控制层
  核对原操作与实际状态；同一 boot 内“重开”本身不证明之前的目录项已经持久化。
- Linux 逐组件拒绝符号链接及不安全 owner/权限，私有文件拒绝硬链接和特殊类型。
  root-owned sticky 祖先允许；任意可写祖先不因测试环境特殊而放行。同 UID 恶意进程、
  挂载替换和任意文件系统的断电保证超出此存储边界。

## 验证与后果

已执行路径、只读、权限、不可变发布、完整引用、损坏、故障边界、实际 flock 争用及
持锁子进程 kill/wait 后重开。第一次沙箱运行因 owner 映射被安全拒绝，保留原失败；
真实宿主普通 UID 下重新执行通过，没有修改系统权限或降低检查标准。

故障钩子验证写入与发布的有限顺序，不等同于断电实验；writer 重开同步的错误处理
经源码审查，未执行该特定打开时点的 I/O 注入。Linux 之外的权限、锁及持久化行为
尚未验证。后续 T025/T027 在这些原语之上实现运行登记和操作记录，不绕过单写入者。
