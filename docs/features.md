# Hoopa 功能规划

状态：规划，尚未实现。本文面向使用者描述目标体验与验收标准；命令和界面名称均为拟议接口。
Hoopa 面向 Linux SSH、日常终端和 Agent 工作流，以 CLI 为主要入口，按需提供 TUI。
P0 组合原型先验证核心保证，P1 再交付基础管理，P2 扩展可靠计量与界面，P3 验收其他平台与迁移。
P1 完成不代表整个项目完成；没有运行证据的能力保持“未验证”。

## 功能地图

| 模块 | 阶段 | 用户可获得的能力（全部为规划） |
| --- | --- | --- |
| 运行管理 | P1 | 显式启动、停止、重启；查看进程归属、冲突与恢复状态；区分管理器退出和停止转发 |
| 订阅与节点 | P1 | 多源导入、手动更新与小时级更新周期；搜索节点、地区与来源；区分 active 与 pending |
| 逻辑组选路 | P1 | 稳定 US / JP / BEST 组、手选与自动选优、跟随关系；支持应用选择 group 或固定节点 |
| 规则与配置 | P1 应用，P2 源进程 | 应用/进程/域名/IP 统一有序本地规则；有限 DNS 配置；plan、显式 apply 与失败 rollback |
| 应用与 Agent 接入 | P1 | profile 的独立选路、managed / inherit / direct；预览环境和入口；透传信号与退出码，不计量也可独立选路 |
| 诊断与观察 | P1 基础，P2 质量视图必需 | P1 缓存节点探测与基本连接链；P2 进程访问延迟、实际节点与质量比较；只读诊断不触发 probe |
| 应用入口计量与流量统计 | P2 必需 | 入口/源进程/域名完整记录、窗口字节量与速率、排序下钻；P0 验证采集、归属、计数世代、事务与 gap |
| 交互与自动化 | P1 / P2 | JSON v1 与 shell 补全属于 P1；按需 TUI 属于 P2，与 CLI 共用用例 |

订阅只提供节点，本地管理规则、逻辑组和跟随关系。首次支持经验证的 Clash/Mihomo 节点 YAML，其他格式逐项增加。
节点标识与显示名分离；重复名称不覆盖，无法识别地区时显示 unknown，名称或旗帜不证明真实地理位置。
自动更新成功只代表候选已就绪；需要中断连接的变更默认保留 pending，等待显式应用或预先配置的中断策略。
BEST 首期按已验证的探测延迟与健康状态选优，不承诺模型可用性、带宽或费用最优。
缺少 required 组、手选失效或引用错误时阻断变更，保留可用快照，不暗中直连或更换供应商。

## P1 重点流程与验收

### 1. 首次 init 引导

目标是让首次使用者完成一条可解释、可复用的接入路径：

1. 查看核心二进制路径、版本与兼容性；缺失时指向 Rotom 的固定版本安装流程。
2. 添加订阅来源，再由用户单独执行 update，或在引导中明确确认后抓取；显示来源、更新时间和节点概况，秘密输入避免出现在命令行或日志中。
3. 展示 US / JP 候选、地区未知节点与缺失项，让用户确认手选、自动和 required 设置。
4. 生成 plan，说明本地规则、有限 DNS 配置、逻辑组和预期入口；先修复阻断项。
5. 由用户显式执行 apply / start，再展示一个应用运行示例及实际入口。

验收要求：

- 交互引导和无交互参数调用复用同一用例；无交互模式遇到缺少必要输入时明确失败，不等待提示。
- init 不暗中安装核心、启动转发或应用候选；Rotom 负责安装，Hoopa 消费明确的路径和版本。
- init 默认只配置与预览，不自行更新订阅；无交互调用也必须显式声明更新请求，不能以添加来源推导出下载授权。
- plan 仅使用已有本地材料；下载由显式 update 完成，不在预览时触发网络刷新。
- 不修改系统代理、父 shell 或现有应用的持久配置；示例仅影响目标子进程。
- 没有可用快照或必需地区缺失时，明确说明下一步，不用空组或直连凑成成功。

### 2. 路由解释

用户输入域名、IP 或查看一条连接时，应能理解“本地规则可能如何匹配”和“核心实际观察到了什么”。
解释展示规则来源、顺序、可能匹配项及逻辑目标；实际连接证据另列时间、核心记录、命中规则与所选路径。
静态解释不冒充一次真实连接的结果；域名解析结果、目标 IP、嗅探或进程信息不足时，明确列出未知条件。

验收要求：

- 仅有域名时，不因一条 IP 规则就断言实际命中；进程规则缺少进程信息时也不输出确定结论。
- 实际连接证据注明采集时间和可见范围；未记录连接不等于请求没有发生。
- `status` / `doctor` 保持只读，不触发 DNS 解析、健康检查、订阅更新、选优或恢复。
- 主动连通性与出口检查使用单独、显式联网的 probe 命令，说明目标与可能产生的请求。
- 有限 DNS 配置仅暴露经固定核心版本验证的选项；不把任意核心配置透传当作首期能力。

### 3. 切换影响预览

切换订阅、应用更新或修改组策略前，plan 应展示候选与 active 的差异及受影响对象。
预览包括节点增删、手选失效、required 组缺失、跟随组变化、当前 pending 和可回滚快照。
手选固定具体节点与跟随逻辑目标分开表达；跟随 US 的别名继续引用 US，不复制此刻的节点。

例如：active 来源 A 有 US，候选来源 B 没有 US，且 US 为 required。
预览应列出“US 缺失”、跟随 US 的业务组及阻断原因；apply 拒绝候选，A 的完整活动快照继续保留。
不能自动选择 B 的其他地区、改用其他来源或降级为直连。

验收要求：

- 预览明确是否需要受控停止与重启、哪些应用受影响、新连接与长连接分别可能发生什么。
- 首期跨供应商或多组拓扑切换允许已披露的连接中断，不承诺无缝切换或连接迁移。
- 下载成功、候选有效和实际生效分别显示；pending 不表示已更改运行路径。
- 应用失败后只有旧运行态验证恢复才显示 rolled_back；恢复失败显示 degraded 并保留证据。
- 显式 restart 说明中断影响并核对进程归属；归属不明时不杀外部进程、不抢端口。

### 4. 应用接入预览

每个应用 profile 在启动前可预览目标环境、代理入口、NO_PROXY 策略、计量状态和配置 revision。
managed 清理冲突代理变量并设置 Hoopa 入口；inherit 原样继承父环境；direct 移除已知代理变量及适配层覆盖项。
预览列出增删的环境变量与绕过范围，认证信息及订阅秘密脱敏，不输出完整父环境。

验收要求：

- managed不计量直接使用Mihomo；完整计量候选也直接进入已验证事件能力的Mihomo入站，身份/字节/计时/实际链同源。GOST仅保留可选兼容和累计对照；缺完整能力明确失败，不能静默退化成只显示总量。详见[ADR 005](adr/005-telemetry-replan.md)。
- inherit / direct 不承诺经过 Hoopa，与启用入口计量的组合报配置错误，不静默降级。
- 计量开关和入口变更标明“仅下次 launch 生效”；旧进程、后台后代与长连接不自动迁移。
- NO_PROXY 绕过及应用自身绕过不在入口计量范围；不遵守代理变量的应用明确标注限制。
- direct 不承诺绕过已有 TUN、VPN 或应用自身代理；三种模式都不改父 shell 和系统设置。
- 启动以参数数组传递，终端中断、信号和退出码可观察；进程启动成功不等于代理联网成功。

应用独立计量与独立选路分别验收。profile 选择 group 或固定节点属于 P1 必需能力，P0 先验证独立可识别的 Mihomo 入站。
不计量路径也须支持独立选路且不依赖 GOST；不能仅凭 profile 名或代理环境变量宣称已隔离路由。

## 应用与进程路由规则

应用 profile 选路为 P1 必需；匹配实际业务源进程为 P2 必需，P0 提前验证源身份能否贯穿转发链。
应用、进程、域名和 IP 条件进入统一有序的本地规则列表，按书面顺序取首个匹配，不隐式采用“更具体自动优先”。
规则目标支持逻辑 group，或 provider 与稳定 node_id 组成的固定节点身份；优先推荐 group，仍保留固定节点选择。
规则只约束进入 Hoopa 的连接；direct、inherit 或其他绕过路径不被强制接管，不默认引入 TUN。

验收要求：

- 进程匹配使用实际源身份，不能将 GOST PID 当作业务进程；应用标签和源进程证据分别展示。
- 未取得所需进程身份时显示 identity_unavailable，拒绝相关不可判定连接，不默默回落直连。
- 缺失目标组、固定节点或 required 候选时拒绝变更，保留旧快照，不换供应商或暗中直连。
- plan 与路由解释显示规则顺序、命中或不可判定原因、目标及预期链；实际连接另列观测到的规则和链。
- 切换预览说明受影响的应用、进程与连接；不承诺已建立连接随规则或 group 当前选择迁移。
- P0 验证独立入站和源身份，P1/P2 按阶段验收；无法取得关键证据时需裁决设计，不能降为可选能力。

详细规则边界与验收见[应用与进程路由](routing.md)。

## 状态、日志与按需界面

状态分别呈现管理服务、Mihomo、订阅、活动配置、应用入口、采集器与账本，并显示观测时间和新鲜度。
应能区分 stopped、冲突、pending、degraded、stale 和不可用；转发正常时仍可能计量 stale，不能只给一个 running 布尔值。
入口用量同时显示已知累计、覆盖区间、最后样本、开放及永久缺口；未知不是零，也不是可推算的准确账单。
P0 先验证世代识别、checkpoint / delta 同事务、重试不重计与 gap，再决定 P2 历史账本细节。

日志按组件、级别与操作筛选；连接记录注明核心可见性，诊断导出默认脱敏并预览内容。
避免导出订阅凭据、节点认证、controller secret、应用请求内容或完整敏感环境。
P2 TUI 规划概览、订阅节点、策略组、应用、用量和日志页面，只调用 CLI 共用的管理用例。
TUI 不建立另一套配置或恢复规则；危险操作沿用影响预览，退出界面不停止代理。
JSON v1 面向 agentcfg 等调用方，提供版本化请求、错误与可查询操作状态；shell 补全复用命令定义。
自动化不直接读写内部配置或数据库，运行应用的输出也不混入管理 JSON 响应。

## 进程与域名流量视图

这是 P2 必需能力，P0 必须提前验证采集可行性；不能在实现受限时默默降为可选面板。
记录范围是经过 Hoopa 计量入口的 TCP 流量，不是全机器审计，不扩展为默认 TUN、root 权限或 UDP 捕获。
连接记录与历史累计分开展示；短连接结束或进程退出后，历史仍须按保留策略可查，活动连接快照不能代替完整记录。
CLI、JSON 与 TUI 使用同一份事实和统计口径；TUI 用量页提供下列视图，不另外维护一份账。

### 进程身份与合并

- 默认按源进程实例展示（per-source-instance），包含 PID 与进程名；身份须结合 PID 和启动身份，避免 PID 复用混账。
- 原始记录保留各实例，不同可执行路径、用户、启动时间的区别可查询；同名合并只发生在查询展示。
- 同名汇总可展开 PID 列表与各实例，显示当前筛选范围内的贡献；名称相同不表示身份相同。
- 主进程与子进程分别保留来源，可查看一次 launch 的进程树汇总；汇总不再次计入实例已经记录的字节。
- GOST 转发进程不能冒充真正发起业务请求的源进程；profile 或 launch 标签不能替代源进程证据。

### 字段、筛选与排序

| 视图 | 必需信息与操作 |
| --- | --- |
| 进程 | 进程名、PID、实例身份与运行/退出状态；可展开路径、用户、启动时间和所属 launch |
| 域名 | 原始域名与规范化域名、来源证据；仅有 IP 与域名 unknown 分别成桶 |
| 共用统计 | 上传、下载、总字节；上下行速率；连接数；首次/最后活动；采集来源、覆盖区间与质量 |
| 交叉查询 | 按时间、入口、进程实例/同名组、域名筛选；从进程下钻域名，也能从域名下钻进程 |
| 排序 | 总/上传/下载字节、上下行速率、连接数，以及适用的名称/PID；均支持升序与降序 |
| 分页与 TopN | 使用稳定排序和分页；TopN 显示其余项的总量及全量总计，不丢隐藏项贡献 |

速率注明采样窗口与新鲜度；采集暂停或窗口不足时显示不可用，不能把累计除以任意时间伪装成实时速率。
连接数说明统计口径，区分当前活动与历史连接；筛选和同名合并不能改变原始连接事实。
规范化不覆盖原始域名；不以反向 DNS、共享 CDN IP 或 IP 归属猜测业务域名。

### 完整性与验收

- 字节未知、进程未知、域名未知、协议开销/未分配和采集缺口分别表达，不能全部塞进一个 unknown。
- unknown 必须有原因、影响范围和质量标记；用合成及真实应用证据证明采集边界，不能以 unknown 逃避完整性验收。
- 原始事实与入口总量可对账，展示已分配、未分配和差异来源；计数边界不同的值不硬凑相等。
- 进程表与域名表是同一流量事实的不同投影，不能相加；交叉筛选、展开与汇总不重复累计。
- 验收覆盖短连接、退出进程、PID 复用、同名多实例、主子进程、仅 IP、域名缺失及采集中断。
- 同一筛选范围切换排序、分页、TopN 或合并方式后，全量总计保持一致；隐藏项和未知项仍可追溯。
- 查询沿用只读原则，不通过补做联网探测、恢复或修改原始记录来完善统计；缺失证据如实标明。

具体采集证据、归属边界与对账验收见[进程与域名流量统计](traffic-statistics.md)，入口世代和账本约束见[入口计量](metering.md)。

## 延迟与连接质量

P2 必须支持按进程查看实际访问延迟、单位时间流量和实际连接节点，以判断连接与节点质量。
P1 提供缓存的节点探测结果与基本连接链；P0 提前验证计时与实际路径的可观测边界，不提前承诺测量精度。
业务实际访问与独立节点 probe 分开展示，节点探测结果不能填入各进程的访问延迟。

| 维度 | 展示与验收要求 |
| --- | --- |
| 访问耗时 | 连接建立耗时、首字节时间等逐项标明测量边界、来源与单位；HTTPS 或连接复用导致不可见时为 N/A，不是 0 |
| 延迟汇总 | 按目标、窗口、协议与测量定义展示样本数、成功/失败/超时数、p50/p95 及新鲜度；不可比样本不混算 |
| 单位时间流量 | B/s 与窗口内上传/下载/总字节分别显示，可选 1s / 10s / 1min 等明确窗口；缺样不补零 |
| 实际路径 | 每连接的实际 node、provider、逻辑 group、完整链、命中规则与配置世代；缺失证据显示原因 |
| 多节点分布 | 进程或域名跨多个节点时可下钻各节点的流量、延迟与失败分布，不能只显示 group 当前 now |

验收要求：

- 历史连接保留当时实际节点和链，与 group 现在的选中项分开；节点切换后不能改写旧连接归属。
- 同名进程、域名或 launch 聚合使用相应原始样本与统一窗口，不能平均各项 p95 或多进程平均速率。
- 质量比较保留失败和超时，不能丢掉失败请求让节点显得低延迟；样本少、过期和不可比均可见。
- 实际访问与 probe 均注明目标、时间窗口、协议和测量定义；不同定义的延迟不直接排名。
- 查询、`status` 与 `doctor` 不自动联网测量；新增 probe 仍须显式执行，未测与不可测不显示为零延迟。
- 验收覆盖 HTTPS、复用、超时、多节点切换、并发进程、缺样与同名汇总，并核对窗口字节与流量事实一致。

测量口径与质量边界见[进程与域名流量统计](traffic-statistics.md)；目标选择与实际链解释见[应用与进程路由](routing.md)。

## 范围与参考

基础管理不依赖 GOST、SQLite 或 TUI；不默认启用 TUN、系统代理、自启动或系统计划任务。
不增加云同步、远程控制、任意脚本插件或插件市场；不以扩大界面功能绕过 P0 门槛。
构建目标是生成一个 `hoopa` 程序，外部核心按固定版本管理；这不表示把构建二进制提交 Git。

Clash Verge Rev 的参考事实与 Hoopa 的建议分开：

- [本地自定义规则](https://www.clashverge.dev/guide/rules.html)说明本地规则可在订阅更新后保留，启发 Hoopa 将本地规则与订阅节点分开管理。
