## 已通过的首次使用旅程

普通与 race 构建分别使用新的0700临时状态目录、固定实际 `cmd/hoopa` 和已批准 app-routing-v2 核心，从空状态执行公共命令，没有用内部初始化 API 代替 `init`：

1. 声明三个 loopback 端口并在调用 `init` 期间由测试持有原 socket。初始化完成但不监听端口，不发布运行配置或启动核心。
2. 在只有草稿的情况下，`run --mode direct` 和 `run --mode inherit` 启动真实子进程，环境符合声明、退出17保留，没有服务或核心前置依赖。未 Apply 的 managed 请求明确拒绝，目标 sentinel 不执行。
3. 显式启动公共 `service run`，使用 `config plan --input … --output …` 和已展示摘要进行 `config apply`。没有隐式启动或自动批准替代这些命令。
4. 通过实际 managed `run` 启动独立客户端。它只在子进程中消费注入的入口认证，向本次自建127.0.0.1 HTTP服务发送一次请求；两种构建均收到预期 body，目标请求计数均为1。验收驱动不读取或复制凭据文件内容。
5. `app inspect`／`status` 保持受保护树的元数据只读；新 run 不改变原核心身份或已提交 generation。父环境及代理变量前后相同，没有调用系统代理修改命令。
6. 使用公共核心 stop 和 service stop 收尾，分别通过保留的原 pidfd 确认终末，原 service Wait 返回0，没有紧急信号清理回退。

最终通过批次为 `first-use/normal-02` 和 `first-use/race-01`。此前 `normal-01` 私有驱动在末尾收尾时将文件句柄变量遮蔽为 bytes，调用 close 失败；该轮保持失败，原件保留。只修驱动变量命名后，普通和 race 重新完整执行。没有因该驱动问题修改产品或弱化断言。

每种构建完成14次 CLI 调用：11次退出0、两次草稿应用退出17、一次预期的 managed 拒绝退出4；读取3条启动记录，5次只读树对照均无变化。稳定输入与证据独审通过，机器索引见本地首次配置验证记录（本地原件 `../../experiments/gost-mihomo/us2-onboarding-local-validation.json`，不随Git上传）。

这条旅程不依赖 GOST、数据库或 TUI。输入的直接路由仅面向受控本地目标，不能证明外部供应商节点、真实模型服务或其他客户端已经可用。
