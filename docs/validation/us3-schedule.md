# US3：有界订阅调度模块

2026-10-28，T042 内存调度模块验收完成；机器记录（本地原件 `../../experiments/gost-mihomo/us3-schedule-validation.json`，不随Git上传）绑定实现、测试、命令与独立审查。[调度契约](../../specs/001-hoopa-proxy-manager/contracts/subscription-schedule-v1.md)规定时钟、并发、取消及错误边界。

`schedule.New` 只接受未运行的来源状态、显式时钟和下载/验证回调，不创建定时器或系统任务。周期为 null 时不调度；正整数小时须能安全转换为 duration。`RunDue` 固定本次截止时间和来源列表，全局最多两个 worker、每来源一次；排队来源仅在实际开始时占用本次周期。错过多个周期只补一次，下一次到期从本次实际开始计算，不追放历史队列，也不把本轮执行期间新到期的来源加进来。

状态锁不跨下载、验证或时钟回调；查询可以在下载受阻时读取独立副本。重复 `RunDue` 返回 busy，不启动另一批。取消会停止尚未开始的工作，并等待原回调退出后释放本批所有权。单个来源失败不会阻止其他来源；错误只返回固定类别和标准 context cause，不暴露 URL、正文或回调私有错误链。

已下载、已验证、待应用和已应用分别表示。只有验证成功且返回合法 snapshot ID 才更新 latest/pending；失败保留上一份可用快照。RunDue 没有 Apply 回调，不能更改 applied 或中断连接。完成时间不可表示、时钟回退、取消后返回成功等情况均有明确拒绝语义；Downloaded 表示管理器接纳了下载阶段完成，不表示网络是否已收到任何字节。
