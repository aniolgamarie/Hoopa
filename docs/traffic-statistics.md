# 进程与域名流量记录及统计

状态：必需的产品与数据设计，完整能力尚未实现；采集路线按[ADR 005](adr/005-telemetry-replan.md)重规划为同一数据面事件。接收journal子断言通过不等于进程/域名完整。用户要求流量记录明确完整，支持进程、域名、同名合并、排序及统计。本要求补充[入口计量设计](metering.md)，属于 P2 的完成条件，采集可行性必须提前在 P0 验证。

## 1. 完整性的范围与验收

统计范围仍是经过 Hoopa 计量入口的、已验收 TCP 流量。NO_PROXY、direct/inherit、应用绕过入口以及尚未覆盖的 UDP/QUIC 不属于已采集总量；界面和 JSON 必须显式显示范围。该需求不扩大为整机网络审计，不默认要求 root、TUN 或解密 HTTPS。

范围内的完整性包含三层，分别验收：

- **字节完整性**：入口累计、连接增量、协议开销及未分配项可对账，短连接和退出进程不能从历史消失。
- **归属完整性**：每条记录有原始来源身份或明确的未知原因；受控的支持场景必须能识别真实业务进程和可观察目标域名。不能通过把所有记录归入 unknown 来通过验收。
- **恢复完整性**：重试、管理器重启、进程退出和 PID 复用不重计、不串账；无法恢复的字节单独记 gap。

字节已测但进程未知、域名未知，与字节本身无法恢复是不同状态。显示已知字节、未分配字节、各维度归属覆盖率、缺口区间和数据新鲜度；字节未知不填 0。完整性未过关时，入口总量可作为独立能力展示，进程/域名统计不能标为已完成。

## 2. 进程身份与记录字段

原始事实按**源进程实例**保存，不按可复用 PID 或可修改的显示名保存。进程实例键至少包含主机实例、系统启动身份、PID 命名空间（适用时）、PID 与 OS 进程启动身份。Linux 的启动时间校验和其他平台等价方法由平台适配层验证。

`source_process_instance_id` 默认表示原始 TCP 连接发起进程（connector），即发起该次 connect 的 PID 与 OS 启动实例，与计数来源的 `process_run_id` 严格区分。进程名和可执行路径保存建连时快照及取值来源；同时保存可取得的用户、命名空间及身份信息。退出、exec、名称变化或 PID 复用均不改写该连接的历史快照。此口径不识别逐字节 writer，也不以查询时 FD 所在进程替代 connector。

名称与路径还须保存定义版本及各自可信状态。[ADR010](adr/010-restricted-identity-profile.md)已选择下一 Linux 候选的程序名为同次 executable 路径 basename；kernel comm、应用显示名独立保留。解释器名表示解释器，原路径字节、删除后缀及 UTF-8 不可用状态不丢弃。这项工程决定尚未成为正式能力，不能重标旧 unverified 记录或用其他来源补填名称。

| 字段组 | 必需内容 |
| --- | --- |
| 业务关联 | app profile、launch ID、endpoint/service/epoch、源进程实例 ID |
| 源进程 | PID、进程名、启动身份；可取得的父进程/路径/用户/命名空间及来源 |
| 流量 | 上传、下载、总字节；方向已验证，单位明确；瞬时速率与统计窗口分开 |
| 连接 | 采集源世代及原生连接标识、入口连接标识、协议、目标、开始/结束、关闭状态 |
| 线路 | 实际规则/逻辑组、叶子节点与订阅身份、连接代理链及路由世代；未知与当前意图区分 |
| 时延 | 指标定义、测量范围/阶段、起止事件、耗时、结果/超时及来源，和字节事实关联但不相加 |
| 归属 | 进程和域名各自的证据来源、状态、未知原因及归属版本；进程口径 `basis=connect_initiator_v1`、建连快照/观测时点及 FD 共享转交观测状态 |
| 质量 | 采样/事件序号、观测时间、计数边界、精度、缺口、对账状态 |

主进程、子进程和后台后代分别保留。默认进程视图按已验证的 connector 实例统计：子进程自己 connect 归子进程；父进程 connect 后由子进程写数据，该连接仍归父进程 connector，这需要真实建连证据，不能默认套用父进程。另可查看某次 launch 的进程树汇总。若只能证明连接属于某次 launch，记录 `launch_only`，PID/进程名显示未解析，不能套用 launcher、父进程或 GOST 的 PID。

FD 转交、fork 共享及后续写入者变化不改变已验证 connector 的连接归属，也不因共享本身自动记为 unknown。界面与 JSON 始终说明此口径及共享/转交限制；没有监测转交时明确显示 `fd_transfer_observation=unverified`，不承诺自动发现所有转交。仅在 connector 不明、建连事件丢失、后端 generation 不符或原 accepted socket 关联存在多解时保留进程未知原因与候选证据；未知字节只计一次，不平均分配或给每个候选重复计数。

并发launch通过经验证的入站/认证或进程登记关联；共享profile只证明应用上下文，不默认证明launch。独立入口也不能单独证明每个socket的实际子进程。无法关联保留launch_unknown，不把已知PID替换成profile或launchID。新计数边界与旧GOST入口原始字节分源保留。

## 3. 域名身份与边界

每条流量事实保存原始目标、规范化目标域名、目标 IP/端口、域名证据来源及其可见范围。规范化统一大小写、IDNA 和末尾点；展示可保留原文。IP 字面量单独显示，不能伪装成域名。

域名来源需区分代理请求目标、HTTP authority、CONNECT 目标、SOCKS 域名请求、可见 SNI 或核心元数据。只使用实际取得且可关联该连接的证据；不能凭反向 DNS、共享 CDN IP 或当前 DNS 缓存猜出历史域名。

一个域名可能有多个 IP，应汇总到同一规范化域名；一个 IP 可能服务多个域名，不能据此合并。默认以完整主机名分组，不能简单取最后两段作为网站身份。

域名视图表示**可观察目标域名**。隧道目标、TLS 握手信息与加密连接内的每个 HTTP 请求来源并不等价；多路复用或共用连接出现多个目标时，需要可验证的分段事实。无法分段则保留 tunnel/connection 范围标识或域名未解析，不将整条连接复制到每个域名，也不将后续字节全部贴到第一个域名。

不能获得域名时显示目标 IP、`domain_unknown` 及原因，如仅提供 IP、协议不可见、元数据缺失或关联失败；仍能查询这些字节。采集元数据限制为统计所需字段，不记录 URL 查询参数、请求正文、令牌或应用 prompt。

域名分桶类型为 `host / ip_only / unknown`，同一事实只进入一种类型；有目标 IP 但没有域名不意味着同时进入 IP 与未知两个桶。

## 4. 查询、合并与展示

CLI、JSON 和 TUI 使用同一查询语义；P2 必须提供以下视图。

| 视图 | 展示与操作 |
| --- | --- |
| 进程实例 | PID、进程名、启动时间、运行/退出状态、上传/下载/总量、速率、连接数、活动时间、归属质量 |
| 同名进程合并 | 按明确的进程名规范聚合，显示实例数、PID 列表、不同路径/用户提示，可展开各实例 |
| 域名 | 完整域名或 IP/未知桶、上传/下载/总量、速率、连接数、相关进程数、活动时间、证据范围 |
| 进程 × 域名 | 从进程查看目标域名，或从域名查看访问它的进程；支持交叉筛选和下钻 |
| launch / 进程树 | 单次启动及其已验证后代的汇总，可展开实际进程，不重复累加父子汇总 |

原始记录始终保留每个进程实例；同名合并是查询选项，展开与合并前后总字节一致。Linux 首期在相同名称来源和定义版本内按记录的名称精确且区分大小写分组，其他平台须定义自己的规则；相同文本的 executable 名、comm 和应用显示名不能混合。相同来源、版本和名称但不同路径或用户的进程可在该视图合并，但必须标识差异，并允许按路径/用户继续拆分。历史同名重启也保留实例数，PID 列表不能代替实例唯一键。

筛选至少覆盖时间范围、app/launch、源进程实例、PID（须限定主机/启动身份或列出匹配实例）、进程名、域名、入口、协议和质量状态。可从包含未知桶的全量结果开始，再显式筛选已识别部分；默认不能隐藏未知行或已退出进程。

排序支持适用视图的总字节、上传、下载、上传/下载速率、连接数、名称、PID、最后活动时间，以及已具备样本的同口径延迟和失败率，均可升降序。缺样/不可比较项保留状态，默认排在已知值之后，不当作 0。区分活跃连接数、窗口内新建连接数和累计去重连接数；进程数按实例键去重，同名合并后不将同一连接多次计入。速率使用明示窗口，同一排名使用同一数据截止点；停采不显示 0 B/s。

默认按所选时间窗口总字节降序，次级排序使用稳定的实例/域名键。分页游标绑定过滤条件、合并方式、排序和数据版本，刷新时重新开始，避免排名变化造成漏行或重复。Top N 同时显示全量总计、未展示部分和未知项，不把 Top N 的小计当成总量；百分比明确分母与覆盖范围。

活动时间按可靠事件记录首次/最后活动；若来源只有采样时间，则标为首次/最后观测及精度，不能伪装成精确 socket 活动时间。历史范围与实时窗口分开，跨采集缺口的速率或时间桶不补造。

## 5. 同一份事实与对账

进程、同名组、域名及其交叉统计均从同一份去重字节事实投影。每个事实记录 source/epoch/connection、区间或序号、双向字节增量、进程/域名维度、计数边界及质量。不同时累计“进程总表”和“域名总表”形成新的总流量；两张表是同一批字节的不同视图。

在相同计数口径和截止点，对每个方向必须满足：

```text
事实总字节 = 按已知进程分组之和 + 进程未知字节
事实总字节 = 按已知域名分组之和 + IP/域名未知字节
入口累计增量 = 可对账事实字节 + 明确的开销/未分配差额
```

域名未知和进程未知可落在同一个事实中，各自在所属维度计入一次；不能把两个未知桶相加成额外流量。协议握手或入口级开销无法关联目标时保留相应未分配事实/差额，并标明是否已经包含在事实总量中，不能重复记。字节自身不可恢复的 gap 另列为 unknown，不参与已知数值的等式。

只有同一世代、方向、计数边界和已对齐截止点才能做等式对账。活跃采样尚未对齐时标 `pending_reconciliation`；GOST 入口量与其他层连接 payload 不同口径时标 `not_comparable`，分别展示，不能按比例摊给域名或进程。差额异常、负差额或明细超总量必须报错并保留证据，不能截成 0 强行平衡。

持久模型补充进程实例、连接/目标元数据、连接检查点、字节事实、归属修订与对账状态。连接检查点和对应增量事实同事务提交，稳定样本/事件 ID 防重；入口 checkpoint/delta 也遵守原有事务。不要求两个独立采集源跨进程原子提交，未对齐状态需可恢复。

晚到 connector 归属信息通过带版本的修订绑定现有事实，不再插入同一字节，也不改写当时的路由决定。每次查询固定数据及归属版本；历史更正可追踪，不能静默改名或跨 PID 世代补填。进程退出或短期 UI 缓存淘汰不得删除账本历史。

明细保留、归档与聚合策略显式配置。在承诺的历史范围内，聚合仍保留进程/域名/交叉维度与未知/质量项，不能仅剩按日总量却继续提供精确下钻。导出提供查询条件、统计窗口、计数边界、数据版本、质量与全量总计；JSON 为必需，其他格式后续定稿。

## 6. 采集架构必须通过的门槛

GOST 服务 metrics 提供入口累计依据，但不能单独生成 PID/域名明细；Mihomo 的活动连接快照也不能证明短连接历史完整。经 GOST 转发后，核心观测的对端可能是 GOST，不能直接作为业务源进程。相关一手资料及核对边界见[上游参考](references.md)。

P0 必须比较可用的连接级采集/记录接口及源 socket 身份关联方式：

1. 在原始应用直接进入候选 Mihomo 的边界，取得 connect 发起实例及名称/路径快照，在选路前验证它与原 accepted socket 的关联；不能只凭时间、端口或 client IP 猜测。Linux 建连事件采集的权限、时序、丢失和短连接竞态必须实测，轮询 `/proc` 的 FD 所在进程不自动证明 connector。GOST 仅保留兼容对照，不替代该边界。
2. 取得同一入口计数口径的连接生命周期、增量及终末值，验证短连接在采样间隔内完成也不会漏。WebSocket 推送快照不等于具备关闭事件、持久序号、重放和确认机制。
3. 验证采集器停机时的缓存/持久记录、重放与崩溃尾段。若仅总量可补回，明细无法补回则记录维度缺口，不将总量补差伪造成完整历史。
4. 将 connector、目标与计量事实关联；验证子进程自己 connect 和父 connect 后子写两个正例，以及 FD 共享/转交后归属不变、未知原因与去重。GOST、profile 或启动器标签不能替代 connector；若启动器本身确实发起 connect，须由同样的原始证据证明。
5. 当现有 GOST/Mihomo 接口无法满足时，主代理重新选择受支持的采集适配方式或提出必要的实现调整；不能在未验证前声称组合已支持完整进程/域名账本，也不能悄悄将该需求移到可选功能。

本阶段不预定特权采集、内核插件或协议解密方案。P0 的输出必须包括“已证明什么、仍缺什么、为通过必需场景需要怎样调整”；P2 在完整进程/域名统计验收通过前不能宣告计量模块完成。

## 7. 访问延迟、单位时间流量与实际线路

这些是 P2 的必需质量视图，P0 先验证数据源和计时边界。P1 可展示缓存的节点探测结果与基础连接链；不能拿节点 probe 的数值填进某个进程的业务访问延迟列。

### 延迟定义与可见范围

所有时延以 ms 表示，附测量类型、定义版本、目标、协议、采集源、观测时间、结果及缺失原因。必须区分：

| 指标 | 定义与边界 |
| --- | --- |
| 节点探测延迟 | 独立 probe 到指定 URL 的核心/API 测量结果；保留源定义和参数，不称为业务 RTT |
| 转发建立耗时 `forward_setup_ms` | 从完整解析代理请求、取得目标主机名/IP 并开始本次转发尝试，到可转发通道就绪；起点不要求 DNS 完成，期间发生的 DNS、排队、代理认证与上游建立均计入，起点前预解析不计入，不能称为纯 TCP RTT |
| 可见请求首字节 `request_first_byte_ms` | 从可关联业务请求的首字节发出，到首响应字节到达；包含请求发送与服务端等待，必须有请求级证据 |
| DNS / TCP / TLS 阶段 | 仅在同一测量范围内取得明确起止事件时分别展示，不以总体耗时相减猜测阶段 |

转发建立耗时以明确的 attempt ID 关联；失败、取消、超时保留实际等待和结果，但不伪装为成功建立样本。客户端迟迟未提交完整代理请求的等待，与完整取得请求目标之后的转发阶段分开，不把应用自身等待都归为网络耗时。

时长由同一采集源的单调时钟计算；UTC 用于关联和展示。跨进程时间戳不能未经时钟与范围校验直接相减。连接开始时间、连接存活时长或最后字节时间都不能替代访问延迟；缺少起止事件时显示 N/A 及原因。

HTTPS 透传、长连接复用或加密多路复用下，可能无法取得每个业务请求的边界。隧道建成、首个加密包或 TLS 握手响应不等于请求首字节；无法证明的阶段保持 N/A。首期不为填满延迟列而解密业务流量。建连前已就绪的复用连接不能生成一个假定 0 ms 的新握手样本。

### 统计与线路质量

进程、同名组、域名及节点视图可查看所选窗口内同口径样本的 p50/p95、最小/最大、样本数、成功/失败/超时/取消数、观测覆盖与新鲜度。成功样本延迟分布与超时/失败分别呈现；超时是被截止的等待，不能填 0、当作某个精确完成耗时，或从分母中悄悄删除。

样本事件有稳定 ID、连接/attempt/request ID 和来源世代，重放不重复增加次数。节点探测、连接尝试、可见请求分别有分母，不能用连接建立成功率冒充请求成功率；HTTP 响应很快也不等于业务成功。失败阶段与可观察的错误类型另列，未知原因保留未知。

同名合并及跨进程统计重新聚合原始同口径样本或兼容的直方图，不平均各行 p95，也不对不同样本数的均值作简单平均。近似分位数须注明算法/误差，样本不足须提示样本数。不同目标、协议、测量阶段、定义版本、probe 与业务数据不能混成一个延迟排名。

判断节点质量时，至少同时展示目标范围、窗口、样本量、失败/超时比例、建立/首响应耗时、实际吞吐及实际线路。服务端排队、目标差异、应用空闲与本地拥塞都可能影响结果；观察到的吞吐不等于节点带宽上限，不根据单个 RTT 或单一综合分数宣称节点优劣。

### 单位时间流量

每个进程/同名组/域名/实际节点均能查看**窗口字节量**与**窗口平均速率**。窗口候选为 1 秒、10 秒、1 分钟，具体可用粒度受实际采样精度限制；显示窗口起止、截止点和覆盖率。刷新每秒一次不代表有逐秒历史精度。

上传、下载分别计算：该窗口可定位的增量字节 / 同一有效窗口秒数，速率用 B/s、KiB/s 或 MiB/s，单位不能混用。合并进程时先汇总相同窗口字节再计算，不平均各进程速率；覆盖不一致时显示部分覆盖，不能用更短的活跃时间除出看似可比的高速率。

跨采集缺口且只恢复了累计总量时，不均摊到每秒，不补零或插值成平滑曲线。只有证明全窗口观测正常且没有流量时才能显示 0 B/s。窗口历史、长期总账和当前速度分别存储或投影，压缩历史须保留承诺的粒度与质量信息。

### 实际节点与规则关联

每条连接保存当时观测到的逻辑组、命中规则 ID、实际叶子节点/订阅 ID、完整代理链、配置/选择世代及证据时间。节点显示名不是唯一身份；记录拿不到时标为未知，不能用当前 group 的 `now` 回填历史。

自动组或配置切换后，现有连接可能继续旧路径，新连接使用新路径。进程汇总出现多个节点时，展示节点分布及各自连接/字节/质量指标，可下钻到连接；不能只显示最新节点而掩盖旧连接。链的方向、完整性和跨切换保留语义需固定版本实测，不能仅凭数组顺序猜测叶子。

路由决策意图与实际观测分别保存：意图用于解释“计划走哪里”，连接链用于证明“观察到走哪里”。实际按应用/进程选路规则见[路由设计](routing.md)，不能因展示当前规则就声称每条历史连接已改路。

只读查询使用已有质量记录；主动 probe 单独执行，保留目标、频率限制和开销，纯测量优先选择经过验证且不改变固定选择的接口。存在清除固定选择副作用的组级端点不用于纯测量路径。采集已有业务流量与创建测试流量是不同操作，不能在打开面板或执行 status / doctor 时触发测速或自动切换节点。
