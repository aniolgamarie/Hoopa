# Feature Specification: Hoopa 整体代理管理产品（P0–P3）

**Feature Branch**: 未创建；本次未配置分支钩子，规格目录与 Git 分支独立

**Created**: 2026-10-22

**Status**: Draft

**Input**: User description: "Hoopa 整体产品规格，覆盖 P0–P3"，包含本轮对话已确认的接入、选路、进程/域名统计和连接质量要求。

本规格定义用户需要的能力与可观察结果。P0–P3 是交付阶段，用户故事中的 Priority 是需求优先级；
本文件与质量检查通过不代表功能、性能或平台支持已通过运行验收。技术实现由后续规划决定，并受项目宪章约束。
2026-10-22用户授权重规划计量部分：完整进程/域名/质量要求保持，具体来源不锁死GOST；新旧计数边界不得混算，实现选择及未验证项见[ADR 005](../../docs/adr/005-telemetry-replan.md)。

## Clarifications

### Session 2026-10-22

- Q: 两个终端或 Agent 同时修改 Hoopa 配置时，基于旧配置提交的后续修改应该如何处理? → A: 拒绝过期修改，返回冲突；基于最新状态重新预览、提交后才能执行。
- Q: 历史记录超过保留期后，Hoopa 应自动清理，还是每次都等待用户单独执行清理? → A: 启用策略及缩短保留期均先预览确认；应用后自动清理到期记录，临时无法清理时明确显示待清理。

### Session 2026-10-23

- Q: “进程级流量/规则”的默认归属口径是哪一种？ → A: 连接发起进程：按发起原始 TCP 连接的 PID/启动实例归属，FD 转交不改写历史，并显示共享/转交限制。名称和路径使用建连时快照；这不证明后续请求或逐字节的写入者。
- 本次明确选择记为 `attribution_basis=connect_initiator_v1`。旧来源/旧验收保留原语义和失败结论，不自动重贴新口径；新用例在运行前登记该口径。选择统计语义不等于授权加载特权后端。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 先确认真实工作流与故障边界（Priority: P1）

交付阶段：P0。作为维护者，我要先用一个真实终端或 Agent 工作流验证转发、计数、质量与选路的关键边界，
并取得明确的通过、失败或未验证记录，避免先交付完整界面再发现核心保证无法实现。

**Why this priority**: 进程归属、短连接、长连接和故障恢复决定产品承诺是否成立。

**Independent Test**: 在独立测试环境中，运行一个真实目标应用及受控流量对照，
演示正常访问、故障、恢复和原始证据；无需先具备完整产品命令或面板。

**Acceptance Scenarios**:

1. **Given** 已固定目标应用与测试材料，**When** 执行一次真实访问及受控收发，**Then** 能分别说明实际路径、已观测字节、进程/域名归属和仍不可见的信息。
2. **Given** 正在转发且有长连接，**When** 管理进程退出、采集停止或转发组件重启，**Then** 每种情况的连接影响、可恢复数据和永久缺口分别有证据，不将失败记为通过。
3. **Given** 某项关键保证缺少证据或无法满足，**When** 评估进入下一交付阶段，**Then** 保留阻断及调整决定，不以完成界面、只展示总量或把全部归属标为未知来代替验收。
4. **Given** 需要按应用/源进程选路及展示访问质量，**When** 执行最小验证，**Then** 证明所需身份在决策前可用、计时边界可观察、实际线路可关联，或明确记录尚待调整的能力。

### User Story 2 - 为目标应用建立局部代理接入（Priority: P1）

交付阶段：P1。作为终端用户，我要完成首次配置，并只为指定子进程选择 managed、inherit 或 direct，
无需修改父 shell 或系统网络设置。

**Why this priority**: 用户必须先能安全、可预测地启动一个真实应用。

**Independent Test**: 从已准备的外部依赖和订阅材料开始，按帮助完成配置、预览、显式启动，
分别运行三种模式并比较父环境、目标环境和应用退出结果。

**Acceptance Scenarios**:

1. **Given** 首次使用且尚未启动转发，**When** 进行初始化与本地预览，**Then** 展示依赖可用性、缺失配置及下一步，不暗中联网更新、启动或应用候选。
2. **Given** 用户显式请求下载、应用及启动，**When** 必需条件满足，**Then** 目标应用可通过 managed 访问，运行前可查看入口、环境变化、绕过范围和计量状态。
3. **Given** 父环境已有代理设置，**When** 使用 inherit 或 direct 启动子进程，**Then** 分别原样继承或清理已声明的代理设置，父环境和系统设置保持不变；direct 不保证绕过既有 TUN、VPN 或应用自身代理。
4. **Given** managed 入口不可用或计量与模式不兼容，**When** 启动应用，**Then** 返回明确失败，不自动改用另一种模式或未计量入口。
5. **Given** 目标收到中断、退出或创建后台后代，**When** 用户观察运行结果，**Then** 退出状态可追踪，未知存活后代及其旧入口不会被静默当作已结束。

### User Story 3 - 管理订阅与稳定逻辑组（Priority: P1）

交付阶段：P1。作为用户，我要切换订阅、手选节点或自动选优，同时保留稳定的 US、JP、BEST 组和本地规则。

**Why this priority**: 节点来源变化不应破坏长期使用的逻辑名称与路由意图。

**Independent Test**: 使用两份来源可区分的订阅，验证节点变化、手选/自动策略、跟随关系及更新失败，
不要求启用计量或交互面板。

**Acceptance Scenarios**:

1. **Given** 两个订阅使用不同的节点显示名，**When** 更换活动来源，**Then** 本地组名不变，所有声明跟随的组一致更新，独立固定目标明确列出。
2. **Given** 候选缺少必需地区、手选节点或引用，**When** 预览或应用，**Then** 列出具体阻断项，活动配置保持可用，不直连、不换来源。
3. **Given** 用户选择自动策略，**When** 候选健康状况变化，**Then** 只在明确候选范围内选择，显示依据与新鲜度，不把延迟最小称为所有业务均最优。
4. **Given** 已启用正整数小时周期，**When** 下载失败或恢复时错过多个周期，**Then** 保留旧快照；每个到期订阅最多补一次，未按错过次数集中重放。
5. **Given** 更新已取得候选且应用会中断连接，**When** 尚无本次显式应用或预设中断策略，**Then** 显示待应用及影响，不将下载成功显示为已生效。

### User Story 4 - 为应用指定组或固定节点（Priority: P1）

交付阶段：P1。作为用户，我要让不同应用 profile 使用指定 group 或固定节点，并能理解规则顺序和例外。

**Why this priority**: 应用定向是基础接入能力，不应要求用户先开启计量。

**Independent Test**: 两个应用 profile、两个逻辑组和一个固定目标，在不启用计量的环境中，
结合有重叠的域名/IP 条件验证实际路径。

**Acceptance Scenarios**:

1. **Given** 两个 profile 配有不同目标，**When** 分别启动并访问，**Then** 实际连接使用对应目标，不因关闭计量而丢失应用上下文。
2. **Given** 应用、域名和 IP 规则有重叠，**When** 改变明确的规则排列，**Then** 第一条确定匹配生效；预览说明遮蔽，不暗中按具体程度重排。
3. **Given** 某应用固定到来源 A 的节点，**When** 活动订阅切换到 B 且存在同名节点，**Then** 固定目标仍是 A 的原身份，或因原目标失效阻止变更，不绑定到 B 的同名节点。
4. **Given** 目标不可达、缺失或必需组为空，**When** 应用候选或建立连接，**Then** 分别拒绝无效变更或报告连接失败，不自动换目标、换来源或直连。
5. **Given** 规则变更前已有连接，**When** 新规则生效，**Then** 展示新旧连接影响及实际路径，不承诺迁移旧连接。

### User Story 5 - 管理生命周期并恢复失败变更（Priority: P1）

交付阶段：P0 验证边界，P1 交付。作为用户，我要关闭界面、重启管理器或应用配置后，仍能判断转发归属、连接影响和恢复状态。

**Why this priority**: 转发可靠性和错误恢复比增加管理入口更重要。

**Independent Test**: 对一个隔离实例执行关闭界面、管理器故障、接管、部分应用失败和回滚失败，
每次都核对实际运行与用户收到的结果。

**Acceptance Scenarios**:

1. **Given** 转发已就绪，**When** 关闭管理界面或短命令结束，**Then** 转发继续，停止整套代理必须是明确操作。
2. **Given** 管理器崩溃且转发仍存活，**When** 重启管理器，**Then** 验证实例身份后接管，不重复启动或误认其他同 PID/同端口进程。
3. **Given** 变更只有部分内容成功，**When** 恢复旧配置，**Then** 只有旧运行态完整核验成功才报告已回滚。
4. **Given** 恢复失败或实际状态无法判定，**When** 用户查询，**Then** 显示 degraded、原因与可采取的下一步，保留证据并停止自动写操作。
5. **Given** 应用结果已发生但响应或确认丢失，**When** 调用方重试或查询操作身份，**Then** 可判定既有操作结果，不重复创建相同运行或假报成功。
6. **Given** 两个调用方基于同一活动配置预览变更，**When** 一个已应用而另一个提交旧候选，**Then** 后者在写入前返回冲突、当前状态保持不变，必须基于最新状态重新预览并提交。

### User Story 6 - 只读排障与非交互自动化（Priority: P1）

交付阶段：P1 基础，P2 增强。作为用户或 Agent 调用方，我要读取真实状态、解释规则和预览变更，
并通过版本明确的机器可读交互管理 Hoopa。

**Why this priority**: 终端与 Agent 工作流需要稳定、无隐藏副作用的操作边界。

**Independent Test**: 在服务未启动、正常、过期和降级状态下读取信息，对照操作前后状态，
并使用满足及不满足已声明授权条件的调用方验证读取、更改、结果与错误。

**Acceptance Scenarios**:

1. **Given** 实例不存在或状态异常，**When** 执行 status、doctor、预览或查询，**Then** 如实报告，且不创建状态、启动、下载、测速、修复或恢复。
2. **Given** 只知道目标域名或部分身份，**When** 查看路由解释，**Then** 区分可确定规则、未知条件和已有连接证据，不将静态推断当作实际访问。
3. **Given** 用户显式发起网络探测，**When** 获得结果，**Then** 标明目标、时间、结果和影响，不因此改选节点或解除固定选择。
4. **Given** 非交互调用提交已支持或未知版本，**When** 执行管理操作，**Then** 支持版本产生稳定可解析结果和错误分类，未知主版本明确失败，且不混入应用输出或等待交互提示。
5. **Given** 用户导出排障材料，**When** 查看导出预览及结果，**Then** 能区分管理、转发、采集故障，秘密、业务正文及完整敏感环境不被导出。
6. **Given** 已声明允许的本地访问范围与调用授权条件，**When** 授权及未授权调用方分别读取或改变管理状态，**Then** 授权操作正常完成，范围外或未获授权的调用均被拒绝，不读取或改变受保护状态。

### User Story 7 - 完整查看进程与域名流量（Priority: P2）

交付阶段：P2，P0 提前验证完整性。作为用户，我要按进程、同名组、域名及交叉维度查看入口流量，
并能辨别已知量、未知归属和无法恢复的缺口。

**Why this priority**: 累计总量只有在归属、完整性与查询一致时才能用于分析。

**Independent Test**: 预先固定可识别样本的进程/目标真值和不可见样本的预期原因；两个同名进程及其子进程
访问两个可区分域名，生成长短连接、退出、重启与采集中断，比较原始事实和各视图的总计、筛选与排序。

**Acceptance Scenarios**:

1. **Given** 同名进程并发、退出后 PID 被复用，**When** 查询历史及同名合并，**Then** 显示 PID、进程名和启动身份，能展开实例，旧记录不串账且合并前后总量一致。
2. **Given** 域名对应多个 IP、多个域名共享 IP 或目标仅为 IP，**When** 查询及双向下钻，**Then** 按有证据的完整域名归属，IP-only 与未知桶保留，不猜补或重复分配字节。
3. **Given** 短连接在两次常规观察之间完成，**When** 查询已承诺的历史，**Then** 终末字节和归属仍可查；缺失时有明确缺口，不能宣称完整。
4. **Given** 计数重新开始、样本重放或保存失败，**When** 恢复采集，**Then** 不产生负数或重复计量，无法恢复的尾段与维度分别显示。
5. **Given** 相同数据截止点和筛选范围，**When** 切换排序、分页、Top N、同名合并或进程/域名视图，**Then** 全量总计一致，隐藏及未知项不丢失，维度总量不相加。
6. **Given** 父进程建连后共享或转交已连接 FD 给子进程，**When** 查看进程归属，**Then** 有原始建连证据时仍归父 connector，并显示这不证明后续写入者；未监测转交时标为未观测。仅有启动上下文、connector 缺失或入口关联多解时显示未知与原因，不猜填父进程或转发器。
7. **Given** 用户启用保留策略或缩短保留期，**When** 预览影响、确认并应用，**Then** 后续按已确认策略自动清理到期记录，保留范围内的进程/域名下钻、质量和缺口仍可用，范围外状态明确，不用每日总量冒充可下钻明细；延长保留期不恢复已清理记录。
8. **Given** 执行前已登记可识别与不可见样本的真值，**When** 验收归属完整性，**Then** 所有承诺可识别的样本均正确归属，不可见样本符合预定未知原因，不在看到失败后删除样本或改称不支持来通过。
9. **Given** 到期清理暂时无法完成，**When** 只读查询或清理恢复，**Then** 查询显示待清理而不执行删除，恢复后仅清理已确认策略允许的范围，未清理和已清理状态可区分；已清理区间不显示为零流量。

### User Story 8 - 按真实源进程执行规则（Priority: P2）

交付阶段：P2，P0 提前验证决策前身份。作为用户，我要按真实进程实例、名称或路径指定 group/节点，
且不把路由显示中的进程名误当成已经按该身份执行。

**Why this priority**: 实时路由必须使用当时可证明的源身份，与事后统计补全分开。

**Independent Test**: 在已验证的源身份场景中，对不同名称/路径及临时进程实例配置规则，
再引入身份缺失、FD 共享/转交、exec/改名和已有连接验证。

**Acceptance Scenarios**:

1. **Given** 路由前可以将建连快照唯一关联到原始入口连接，**When** 该连接进入选路，**Then** 按 connector 实例、建连名称/路径与应用/域名/IP 条件共序判定，并记录快照、命中规则与实际路径。
2. **Given** 当前将评估的规则需要但无法取得源身份，**When** 连接到达，**Then** 拒绝该不可判定连接并显示原因，不将未知作为不匹配进入默认目标；更早规则已确定匹配的连接不受后续条件影响。
3. **Given** 当前环境不支持所需进程匹配能力，**When** 应用含该条件的配置，**Then** 拒绝配置并说明缺失能力，不用永远拒绝所有连接冒充功能可用。
4. **Given** 历史记录后来补到了身份，**When** 查询过去的决策，**Then** 区分事后归属和当时判定，不倒写成过去已按该进程路由。
5. **Given** 某流量使用 direct、inherit、绕过或未进入 Hoopa，**When** 设置进程规则，**Then** 不声称已经强制捕获该流量，也不暗中启用系统级接管。
6. **Given** 父进程建连后由子进程写入或进程随后 exec/改名，**When** 原连接继续转发且另建新连接，**Then** 原连接保持原 connector 快照及规则，新连接使用新建连证据；名称与路径未分别通过能力验收时，不允许加载依赖缺失字段的规则。

### User Story 9 - 判断访问与节点质量（Priority: P2）

交付阶段：P2，P1 可先提供已有节点探测和基础连接证据。作为用户，我要结合进程访问延迟、
单位时间流量、错误与实际节点判断连接质量。

**Why this priority**: 单个探测延迟不能解释慢业务、线路切换或统计缺口。

**Independent Test**: 使用具有不同建立/响应等待和失败结果的受控样本，配合实际业务访问和节点切换，
核对每个视图的口径、统计与实际路径。

**Acceptance Scenarios**:

1. **Given** 节点探测很快但业务等待较长，**When** 查看进程质量，**Then** 分开显示探测、转发建立及可见请求首字节，包含单位、定义、样本数和时间，不以探测值填业务延迟。
2. **Given** HTTPS、复用或缺少起止证据使某阶段不可见，**When** 查看延迟，**Then** 显示 N/A 与原因，不把连接存活时长、加密包或缺值当作业务耗时或零。
3. **Given** 有失败、超时、取消及不同目标样本，**When** 汇总或排序，**Then** 分母与结果分类可见，不混合不可比样本，不平均各进程的 p95 或将失败删除以美化质量。
4. **Given** 有明确窗口内字节及采集缺口，**When** 查看窗口总量和速率，**Then** 分别显示字节、B/s、窗口及覆盖；合并使用相同窗口，缺口不补零、不均摊成逐秒曲线。
5. **Given** 同一进程连接经过不同节点且组选择后来改变，**When** 查询线路与历史质量，**Then** 保留当时可证明的节点、来源、逻辑组、规则和链，能下钻分布，不使用当前选择回填历史。
6. **Given** 实际吞吐受服务端或本地条件影响，**When** 比较节点质量，**Then** 同时显示目标范围、窗口、覆盖、样本量及失败/超时，不以观测吞吐宣称节点带宽上限或以低延迟宣称业务成功。

### User Story 10 - 按需交互而不改变运行语义（Priority: P2）

交付阶段：P2。作为终端用户，我要按需打开交互面板浏览和操作相同状态，关闭后代理仍运行。

**Why this priority**: 交互降低操作成本，但不能成为基础功能依赖或另一套配置来源。

**Independent Test**: 对同一实例交替使用非交互与交互操作，比较状态、预览、错误及历史，再关闭面板。

**Acceptance Scenarios**:

1. **Given** 已有可查询实例，**When** 打开概览、订阅/节点、规则、应用、用量或日志视图，**Then** 与相同截止点的非交互结果一致，未知、过期和降级状态不被隐藏。
2. **Given** 用户进行会改变路径的操作，**When** 从面板预览并执行，**Then** 沿用同样的顺序、校验、影响提示与恢复结果，不产生独立配置。
3. **Given** 面板被正常关闭或异常退出，**When** 应用继续访问，**Then** 转发和已运行的应用不因面板退出而停止，查询也未触发额外测速。

### User Story 11 - 按证据扩展平台并迁移旧工具（Priority: P3）

交付阶段：P3。作为用户，我要知道当前平台实际支持了哪些行为，并能在保留回退路径的情况下迁移。

**Why this priority**: 平台与迁移承诺必须建立在基础管理和计量已验收的能力上。

**Independent Test**: 在每个待支持平台分别核对支持表和真实工作流；
用隔离的旧配置执行预览、备份、迁移及失败恢复。

**Acceptance Scenarios**:

1. **Given** 某平台仅有构建或托管测试记录，**When** 查看支持声明，**Then** 真实应用、退出、休眠和性能尚无证据的项目标为未验证或实验性，不直接宣称正式支持。
2. **Given** 用户只请求迁移预览，**When** 读取旧配置，**Then** 展示差异、冲突和备份计划，不删除旧文件、抢占端口或改变系统代理。
3. **Given** 用户明确执行迁移，**When** 成功或部分失败，**Then** 能验证新运行状态或恢复旧配置，保留可追踪的备份与结果。
4. **Given** 跨平台验证需要托管资源，**When** 安排执行，**Then** 仅使用不额外收费的标准资源或已有免费额度，额度不足标为未验证而非默认付费。

### Edge Cases

- 首次没有可用订阅、未知地区、重复名称、格式无效、超量来源或引用失效时，不能凑出“可启动”的空规则。
- 规则意图、下载候选、实际生效状态和旧连接路径可能同时不同，查询必须明确各自身份与时间。
- 活动来源变更时显式固定节点仍引用原来源；旧来源更新失去节点时禁止以另一个同名节点替代。
- 用户重复提交、调用中断、管理器在确认前退出或回滚也失败时，结果可能不确定，不能简单重做或假报成功。
- 多个终端或 Agent 同时修改时，未应用候选依据的活动配置版本若已过期，必须在写入前返回冲突；不自动合并或覆盖，须基于最新状态重新预览并提交。
- 端口占用、PID 复用、进程启动但身份尚未确认、用户注销和 SSH 断开不能被当成同一种生命周期事件。
- 子进程、共享/转交 socket、后台后代或其他进程使用入口时，启动上下文不等于 connector；已证 connector 不随 FD 共享/转交改变，也不代表后续每次写入者。
- 连接在观察间隔内完成、采集暂停后只恢复总量或计数归零时，字节与维度的可恢复程度可能不同。
- 只有 IP、共享 CDN IP、一个域名多个 IP、加密多路复用和无法分段的连接不得导致猜测或重复归属。
- 进程同名且路径/用户不同、同 PID 不同启动身份、名称变化及历史重启必须可区分；建连时快照不可被稍后的名称、路径或复用 PID 覆盖。
- 时间回拨、恢复后错过多个周期、迟到样本、排序时数据刷新不得引发重复更新、重计或漏页。
- 失败/超时样本、不可见延迟、不对齐窗口、不同计数边界和隐藏未知项不能被处理成零或按比例凑总。
- 已停止实例上的诊断、未安装计量能力的基础管理，以及已有系统 TUN 下的 direct 模式须保持其声明边界。
- 清理达到保留边界、磁盘不足、保存结果不确定或敏感诊断导出时，必须保留可辨认的状态与影响范围；到期但未能清理须标为待清理，不假报删除完成，查询不得触发清理。
- 迁移预览后旧配置继续变化时，正式执行必须重新确认实际差异，不能覆盖未预览的新变化。

## Requirements *(mandatory)*

### Functional Requirements

以下各项均为 MUST；阶段表示最迟交付范围，不表示已实现。P0 只验证最小关键工作流，
无需提前交付后续完整界面和查询体验。正文不规定语言、框架、进程托管、存储或配置生成方法。

**定位与验证（P0）**

- **FR-001**: 产品必须面向 Linux SSH、日常终端和 Agent 工作流，以命令行为主要入口，核心操作可非交互完成。
- **FR-002**: 必须明确区分管理、转发和可选计量能力；基础管理、应用选路及不计量接入不得依赖计量历史或交互面板。
- **FR-003**: 必须在至少一个真实目标应用及受控流量对照中，验证关键身份、字节、连接、质量和路由承诺，再进入相应产品交付。
- **FR-004**: 每项关键验证必须保存输入版本/身份、动作顺序、观察、结果和未验证项；关键前提不成立时保留阻断和调整决定，不降低需求冒充通过。
- **FR-005**: 默认不得启用系统全局代理、TUN、自启动、系统计划任务、特权采集或业务解密；范围不包含新代理协议内核、Web 管理平台、云同步、远程控制平台和插件市场。

**接入与自动化（P1）**

- **FR-006**: 首次配置必须展示依赖与缺失项；本地初始化和预览不自动下载、更新、应用或启动，网络操作需明确请求。
- **FR-007**: 必须支持 managed、inherit、direct，预览目标环境、入口与绕过范围；只作用目标子进程，保持父 shell、系统及既有应用持久配置不变。
- **FR-008**: managed 不可用或模式与计量不兼容必须失败；direct 不承诺绕过既有系统接管或应用自身代理，不捕获未进入 Hoopa 的流量。
- **FR-009**: 应用启动、终端中断与退出结果必须可观察；进程启动成功不得等同代理访问成功，未知存活后代不得被误记为全部结束。
- **FR-010**: 外部依赖的安装与运行管理职责必须分开；消费明确版本与可用能力，不在运行中擅自安装、替换或升级转发能力。
- **FR-011**: 自动化调用必须使用显式版本、稳定结果与错误类别，支持查询已开始操作的状态；未知主版本失败，重复或中断调用不得产生未说明的重复效果。
- **FR-012**: 人类操作与自动化必须具有相同的校验、变更和恢复语义；机器结果不混入交互提示、进度或应用输出，调用方不直接修改内部持久状态。

**订阅、规则与变更（P1）**

- **FR-013**: 多个订阅只提供节点，本地控制规则与稳定逻辑组；显示名变化或重复不得覆盖其他来源/节点的稳定身份。
- **FR-014**: 必须支持手选、自动选优、活动订阅切换及逻辑跟随；所有声明跟随的组一致更新，自动选择只限明确候选。
- **FR-015**: 节点地区未知、必需组为空、手选/固定目标消失或引用无效必须阻止变更并列出原因，不以其他地区、供应商或直连代替。
- **FR-016**: 必须支持手动及用户启用的正整数小时周期更新；失败保留可用快照，恢复后每个到期订阅至多补一次，并限制并发追赶。
- **FR-017**: 必须区分已下载、候选有效、待应用和已生效；有中断影响的自动候选仅按显式应用或用户预设中断策略执行。
- **FR-018**: 应用、域名和 IP 规则必须按公开顺序首个确定匹配，预览顺序与遮蔽；不得隐式按类型或具体程度重排。
- **FR-019**: 应用 profile 必须可选择逻辑组或固定节点，未启用计量也保留应用路由上下文。
- **FR-020**: 固定节点必须绑定来源及稳定节点身份，不随活动订阅重绑定；必须校验所有被引用来源，固定目标不可达时明确失败。
- **FR-021**: 变更前必须展示节点、规则、组、应用和连接影响、阻断项及恢复目标，区分新连接与存量连接，禁止承诺未验证的连接迁移。
- **FR-022**: 必须先验证完整候选再应用；部分成功不能报告整体成功，实际运行核验通过后才报告已生效。
- **FR-023**: 只有旧运行状态完整核验恢复后才能报告已回滚；状态不确定或恢复失败必须显示 degraded、保留证据并停止自动变更。
- **FR-024**: 关闭界面不得停止转发；管理器故障后转发与接管能力必须有实测证据，接管/停止不得仅凭可复用 PID 或端口认领外部进程。
- **FR-025**: 已开始变更的身份和阶段必须可恢复、可查询；响应丢失和重启后不能盲目重复执行，不能声称文件与运行变更是一个不可分割动作；未应用候选在写入前必须核对所依据的活动配置版本，过期则返回冲突且保持当前状态，要求基于最新状态重新预览并提交，不自动合并。

**诊断与保护（P1）**

- **FR-026**: status、doctor、预览和查询必须只读，不启动、创建状态、下载、选优、探测、迁移、修复或自动恢复。
- **FR-027**: 路由解释必须区分配置意图、未知条件和实际连接证据；缺少目标或身份信息时不得伪造确定结论。
- **FR-028**: 主动探测须单独请求，显示目标、时间、范围与结果，不因纯测量清除固定选择或改变线路。
- **FR-029**: 状态必须分别呈现管理、转发、订阅、配置、入口和可用计量组件的健康与新鲜度，不能以单一 running 隐藏 pending、stale 或 degraded。
- **FR-030**: 必须声明允许的本地访问范围与调用授权条件；范围外或未获授权的调用不得读取或改变受保护管理状态，授权调用正常完成；诊断与默认输出不得暴露认证秘密、业务正文或完整敏感环境，订阅不得改写本地安全与路由设置。

**计量与归属（P2，P0 验证可行性）**

- **FR-031**: 计量范围必须明示为经过 Hoopa 计量入口且已验证的流量；首期覆盖已验收 TCP，不称为模型 Token、供应商账单或整机审计，不承诺完整 UDP/QUIC。
- **FR-032**: 计量开关及入口变更只影响后续启动，明确列出旧运行与旧入口；不追溯未计量流量，不自动重启应用或迁移其连接。
- **FR-033**: 字节记录必须关联服务、运行与计数世代，已确认位置与对应增量一起持久确认；重放、重启和归零不得产生负值、重计或跨身份串账。接收日志位置与来源产生位置必须分开，接收重放只证明已送达事件；未送达或来源丢失的数据明确为缺口，不宣称故障零损失。
- **FR-034**: 已识别源进程按 `connect_initiator_v1` 归属于向 Hoopa 原始入口发起 TCP 连接的实例，必须包含 PID、进程名和启动身份，名称/路径为建连时快照，分别保留取值来源、定义版本和可信状态；主/子进程各自建连须分别识别。程序文件名、内核 comm 与应用显示名不能相互代填；下一 Linux 候选的程序名来源按[ADR010](../../docs/adr/010-restricted-identity-profile.md)限定为同次 executable 路径的 basename，能力仍须独立验收。已连接 FD 的共享、转交及后续 exec/改名不改写该连接归属，不声称证明了请求或逐字节写入者。预先定义的可识别样本必须正确归属，证据缺失或关联多解时保留原因，不以启动器、转发器或复用 PID 代填。
- **FR-035**: 域名归属必须保留实际来源与可见范围；完整主机名、仅 IP、未知互斥分组，不按共享 IP、反向查询或当前缓存猜补历史，不复制不可分段流量。
- **FR-036**: 在承诺历史范围内必须保留短连接、退出进程、原始实例和进程/域名关联；临时连接列表和界面缓存不得代替完整记录。
- **FR-037**: 必须区分已知字节、未分配量、进程未知、域名未知、开销和不可恢复缺口，并显示覆盖、新鲜度和对账状态；已知总量不能冒充完整明细，不能事后将可识别验收样本全部改为未知或不支持来通过。
- **FR-038**: 入口与明细必须按相同方向、边界、世代和截止点对账；不可比或未对齐时明确标识，不截零或按比例分配差额。
- **FR-039**: 采集或保存失败不得使已有转发静默改路；位置不得先行推进，能恢复的累计与不能恢复的维度/质量历史分别说明；新计量启动无法确认记录能力时明确失败。
- **FR-040**: 必须按可配置保留策略维护历史；启用策略及缩短保留期前必须预览影响并确认，应用后自动清理到期记录，暂时无法清理时显示待清理，查询不得触发清理；默认按观测时间保留截至观察时刻的滚动 30×24 小时，恰在起止边界的数据属于保留范围，早于起点才过期；延长不恢复已按此前策略清理的历史，相关区间明确不可用；承诺范围内保留进程/域名下钻与质量，不用粗粒度总量冒充可查询明细。

**统计查询与质量（P2）**

- **FR-041**: 必须支持进程实例、同名组、域名、进程×域名和一次启动的进程树视图；同名组须使用兼容的名称来源和定义版本，不能仅凭显示文本混合程序名、comm 或应用显示名。同名合并仅影响展示，可展开 PID/实例与路径/用户差异，不重复计入父子或多维总量。
- **FR-042**: 必须按时间、应用/启动、受限 PID 或实例、进程名、域名、入口、协议和质量筛选，支持双向下钻，默认不隐藏未知与已退出进程。
- **FR-043**: 必须支持适用字段的升降序、稳定分页与 Top N，包括总量、上传/下载、速率、连接数、名称/PID、活动时间及同口径延迟/失败率；保留全量、未展示和未知项总计。
- **FR-044**: 所有视图必须使用同一事实与固定查询截止点/版本；分组、展开、排序和分页不得改变筛选范围的全量总计；连接数明确当前、新建或历史去重口径。
- **FR-045**: 必须分别显示窗口字节量与上传/下载速率，注明 B/s 等单位、窗口、覆盖和截止点；同名聚合使用同一窗口，不平均行速率，不把恢复总量插值成逐秒曲线。
- **FR-046**: 必须区分节点探测、转发建立、可见请求首字节及可验证阶段的时延，标注定义、范围、单位、目标、来源、起止和时间；缺失、不可见或过期状态不当作零。
- **FR-047**: 质量汇总必须提供同口径样本的 p50/p95、最小/最大、样本数、成功/失败/超时/取消及新鲜度；不得平均分位数、混合定义或隐藏失败，连接成功不能代替业务成功。
- **FR-048**: 实际节点、来源、逻辑组、命中规则、链及当时配置身份必须关联原连接；不能用当前选择回填历史，多节点进程可下钻分布，实际吞吐不等于节点带宽上限。

**真实进程路由与交互（P2）**

- **FR-049**: 必须支持以原始连接发起进程实例及其建连时的精确名称或路径快照匹配组/节点；关联证据须在路由前可验证，并与应用/域名/IP 条件共用明确顺序。实例、名称、路径能力分别声明和验收，长期规则不得只绑定可复用 PID。
- **FR-050**: 可能匹配但缺少所需连接发起者或对应快照证据的规则必须拒绝相关连接并给出原因，不能将未知当作不匹配；所需字段能力不支持时拒绝配置，不以永久拒绝所有连接冒充支持。共享/转交 FD 不令已有可信 connector 自动变为未知，但不得据此声称识别了后续写入者。
- **FR-051**: 事后归属补全不能倒写过去路由决策；已绑定连接不因 FD 转交、exec 或改名重选规则，新连接使用其新快照。已应用路由不得逐连接依赖管理器在线，且不声称强制接管未进入入口的进程流量。
- **FR-052**: 按需交互面板必须提供概览、订阅/节点、规则、应用、用量与日志，复用同样的查询、预览、变更和恢复语义；关闭面板不停止代理，非交互使用无需打开面板。
- **FR-053**: 活动/历史记录的导出必须包含筛选范围、窗口、计数与测量口径、数据版本、质量及总计，并保持秘密与业务内容保护。

**平台与迁移（P3）**

- **FR-054**: 每个平台必须分别声明构建、适用集成、真实应用、退出/休眠、恢复和性能证据；证据不足标为未验证或实验性，不以构建成功宣称正式支持。
- **FR-055**: 跨平台验证仅使用不额外收费的标准托管资源或已有免费额度；退出/休眠及实际工作流另在真实环境验收，额度/环境不足不得记为通过。
- **FR-056**: 迁移必须先提供差异、冲突、备份和回退预览；明确执行前不得覆盖旧文件、抢占旧端口或改变系统设置，实际执行失败后旧配置可恢复。

### Key Entities *(include if feature involves data)*

- **订阅与节点**：节点来源及稳定身份，包含来源状态、更新时间、地区证据和是否可用，显示名不作为唯一身份。
- **逻辑组与规则**：稳定逻辑目标、候选/固定选择、跟随关系、有序匹配条件及目标；目标可能为组或绑定来源的节点。
- **应用 profile 与一次启动**：声明的接入模式、计量/路由意图、目标环境及该次运行，不能代替真实源进程身份。
- **源进程实例**：按原始 TCP 建连证据绑定的 PID/启动实例及建连名称、路径快照，含归属口径、字段来源与状态；可关联用户/父子关系，但不从进程树推断 connector，也不当作当前 FD 持有者或逐字节作者。
- **入口与运行世代**：某应用运行使用的访问与计量边界、存活归属和计数连续性，区别于界面或管理器本次运行。
- **配置候选、活动快照与变更操作**：完整目标、当前已核验状态、来源身份、操作阶段、影响与恢复结果。
- **连接与路由证据**：源/目标、生命周期、实际进程、域名、当时规则、节点及代理链，可与当前意图区分。
- **流量事实与归属修订**：可去重的双向字节、观测区间、来源身份和质量，晚到证据只修正归属，不复制字节。
- **质量样本**：某个探测、连接尝试或可见请求的时延、结果、测量定义、目标、线路与覆盖。
- **未知、缺口与对账结果**：字节或维度不可确定的原因、影响范围、可恢复程度及同口径比较状态。
- **查询快照与保留策略**：筛选、合并、排序、截止点、数据版本、展示与全量总计，以及可查询历史范围、已确认的清理策略和待清理/已清理状态。
- **平台与迁移证据**：平台支持项目、实际验证结果和限制，以及迁移预览、备份、执行和回退记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

以下均为待运行验证的验收目标，不是已达成结果。

- **SC-001**: P0 至少完成 1 个真实 Agent/终端工作流和 1 个受控收发对照；关键转发、归属、计数、质量与选路探针逐项有输入、观察和结论，进入后续阶段前无未解决的关键阻断。
- **SC-002**: 在至少 2 个订阅、US/JP/BEST 及节点重名/改名/缺失场景中，所有配置用例保持稳定逻辑名称和声明的跟随关系；静默直连、跨来源后备及固定目标重绑定均为 0 次。
- **SC-003**: 三种接入模式、入口失败和后台后代用例中，目标环境/退出结果符合声明，父环境与系统设置被 Hoopa 隐式修改的次数为 0；所有基础旅程在未启用计量和面板时完成。
- **SC-004**: 至少 2 个应用、2 个逻辑组、1 个固定节点及重叠域名/IP 规则的受控矩阵中，每条实际路径均符合公开顺序；预览对所有已知遮蔽、缺目标和中断项给出明确结果。
- **SC-005**: 下载失败、部分应用、恢复失败、管理器故障、身份冲突及并发过期候选用例中，成功、已回滚、degraded 或冲突均与实际状态一致；误接管、重复启动和假报恢复为 0 次，所有过期未应用候选均在写入前拒绝且不改变当前状态，重新预览提交后按正常校验执行。
- **SC-006**: 模拟错过至少 3 个更新周期后，每个到期订阅至多执行 1 次补更新；每个需中断的候选在未获显式应用或预设策略时均保持待应用。
- **SC-007**: 对未运行、正常和降级实例的所有只读操作，对照观测显示由查询引发的状态创建、下载、启动、探测、改选或修复均为 0 次；自动化响应可解析且不混入应用输出。
- **SC-008**: 按预登记的 `connect_initiator_v1`，在至少 2 个同名进程、2 个目标域名、主/子进程独立建连、父建连后转交 FD、fork 共享、PID 复用及 100 条短连接的受控记录中，可识别样本 connector/建连名称与目标正确率为 100%，终末字节可核验；不可见样本匹配预定原因，事后剔除或重分类以通过、重计、负增量和串账均为 0 次。父建连后子写仍归父 connector；旧口径运行保留原结果，不按新口径重评。
- **SC-009**: 在同一查询快照下，进程、同名合并、域名、交叉视图以及单行分页/Top 1 的已知全量总计一致；隐藏与未知项贡献保留，入口与明细在同口径对齐后全部可解释。
- **SC-010**: 对默认滚动 30×24 小时及用户缩短/延长保留期的受控场景，分别测试早于、恰等于和晚于起点的记录：已采集且未按此前已确认策略清理的边界及范围内记录全部可查询，范围外状态与预览一致；启用及缩短策略均须预览确认，确认前因本次策略变更删除记录为 0 次；应用后自动清理到期记录，失败时显示待清理，恢复后只清理已确认范围，延长不恢复已清理区间；迟到导入和归属修订后仍按原观测时间判断年龄，不延长保留期；跨界区间明确不确定范围，不把已清理、过期或未知数据显示为零。
- **SC-011**: 所有进程路由矩阵用例符合路由前可证明的 connector 建连快照及首匹配顺序；父建连/子写和共享 FD 正例仍使用已证 connector，新连接重新捕获。缺证据、字段不支持、关联多解及事后补全用例中，猜套父/转发器身份、隐式后备或倒写决策均为 0 次；未监测 FD 转交时不宣称已观察其发生或未发生。
- **SC-012**: 同口径质量与窗口流量的受控参考样本中，分组汇总与参考结果一致；平均 p95、平均不同比较窗口速率、超时/不可见填零和缺口逐秒插值均为 0 次。
- **SC-013**: 至少 2 条不同实际线路及切组前后存量/新建连接的用例中，每个可证实历史连接保留其节点与链；用当前选择改写旧路径为 0 次，多线路汇总均可下钻。
- **SC-014**: 交互与非交互完成同一组查询和变更时，状态、质量、影响及恢复结果一致；关闭/异常退出面板对转发造成的停止为 0 次。
- **SC-015**: Linux、macOS、Windows 支持表中的每项正式支持声明均有相应证据；迁移预览的破坏性修改为 0 次，执行失败用例均能核验旧配置恢复；跨平台验证额外付费为 0。
- **SC-016**: 在声明平台、依赖版本、规则规模及 0/1/5 个计量入口的基线中，管理器空闲内存目标 ≤40 MiB、10 分钟平均 CPU <单核 0.5%、整套空闲内存目标 ≤200 MiB；Hoopa 发行包目标 ≤10 MiB、程序目标 ≤25 MiB，外部转发组件另列。所有值必须实测后才可作为结果发布。
- **SC-017**: 完整产品验收时，既定的 33 类故障/边界场景均有可重复结果且无未解决的关键失败；至少 1 名未参与实现的验收者可仅依据帮助完成首次 managed 访问、切组预览和一次只读排障，无需编辑生成文件或内部状态。
- **SC-018**: 在预先声明的授权/未授权读取与更改矩阵中，授权操作全部获得预期结果，范围外或未授权读取/更改受保护状态成功为 0 次；默认输出和诊断导出中的认证秘密、业务正文及完整敏感环境泄漏为 0 项。

## Assumptions

- 本次按用户明确选择创建一个覆盖整体产品的特性规格；各阶段可独立验收，整体范围不等于一次性实现全部功能。需求优先级不替代阶段门槛。
- 初期使用者是本地单用户终端/Agent 操作者及其受信自动化；不包含多租户管理、远程控制、云同步或整机审计。
- 外部依赖由既有安装职责提供固定版本；真实应用、合法测试订阅和可区分的受控目标在 P0 执行前准备。具体工具、进程托管与持久化方法属于后续规划。
- 定时更新由用户明确启用并配置正整数小时周期；未启用时只接受手动更新。中断策略未配置时，需要中断的候选默认等待显式应用。
- 历史保留默认设为可配置的滚动 30×24 小时，这是本规格对原文未指定天数的显式默认，不代表已有运行证据。以记录声明的观测时间及统一 UTC 时间基准判断，保留观察时刻及其之前 30×24 小时的闭区间；恰在起点的数据保留，早于起点过期，不因迟到导入或归属修订重置年龄。策略调整须展示影响，启用及缩短保留期须确认，后续到期清理按已确认策略自动执行；延长仅扩大后续保留范围，已清理历史明确不可恢复。资源成本由原型测量。
- 跨保留边界的区间记录若可精确定位则按事实查询；无法分段时保留原区间、边界不确定性及范围内事实，不比例拆分或补造精确字节。承诺保留范围包含维度、质量和未知信息，不允许仅剩总量却继续承诺明细下钻。
- 流量窗口候选为 1 秒、10 秒、1 分钟；仅对已具备相应观测精度的窗口显示完整值，粒度不足须标明不可用，不用刷新频率冒充历史精度。
- Linux 同名展示默认在相同名称来源及定义版本内按观测名称精确、区分大小写合并，其他平台在正式支持前声明规则；旧记录没有该来源证据时保留原状态，不通过新默认补写历史，合并不更改路由身份。
- 应用 profile 是 Hoopa 声明的上下文，真实源进程身份是另一种证据；专属入口不代表同一用户下的安全隔离。未通过原始身份验证的路径不宣称支持进程规则。
- P1 应用/域名/IP 规则可用不代表 P2 进程规则已可用；某个规则能力不受支持时阻止依赖它的配置，不静默降级。
- 除用户显式要求的输入/输出与网络能力外，初始化、查询和面板打开不产生隐含网络活动或系统配置变更；主动访问、订阅更新和探测分别请求。
- 性能目标是待校验预算，不是已测结果；未达到时记录实际结果、原因与调整方案，不通过丢弃承诺明细或伪造覆盖来达标。
- 治理依据为[Hoopa 宪章](../../.specify/memory/constitution.md)的原则 I–IX；需求来源为[功能规划](../../docs/features.md)、[路由设计](../../docs/routing.md)、[入口账本](../../docs/metering.md)、[流量与质量](../../docs/traffic-statistics.md)和[阶段验收](../../docs/prototype.md)。其中技术候选不被本规格升级为已验证保证。
