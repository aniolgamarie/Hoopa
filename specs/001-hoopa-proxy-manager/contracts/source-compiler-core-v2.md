# T041 sources compiler and protected core v2

Status: finite T041 module accepted, 2026-10-28; see docs/validation/us3-compiler.md and experiments/gost-mihomo/us3-compiler-validation.json. This design document itself grants no core capability; the separate approved-sources-core-v2 artifact binds the tested static hash. Existing basic-v1 artifacts and old binary remain unchanged. New candidate source is a verified independent copy at private/p1-us3-core-candidate/source (1011 base files, pinned build-02-state-history inputs).

## Why a new boundary is necessary

The accepted basic-v1 guard and wire permit only loopback HTTP/SOCKS/Direct nodes, Selector groups and finite fixtures. Native -t accepts more protocols but bypasses that protected launch path. URLTest currently starts alive without a successful probe and falls back to its first candidate when all are unknown/dead. Its Now() changes with background probing. Therefore neither broadening a capability label nor freezing Now() in an immutable snapshot establishes US3 semantics.

## Wire candidate

protocol/sourcecontrol is a separate pure v2 package; protocol/corecontrol v1 stays untouched. Snapshot/Status/Mutation/Result schema_version is literal2, cross-version messages fail. Status mode basic-sources and exact capabilities authenticated-activate-v1, closed-start-v1, immutable-source-snapshot-v2, probe-qualified-groups-v1. These labels describe candidate protocol requirements, not approved installed binaries.

Snapshot retains ConfigSHA256, loopback private controller, 1..4 mixed entries with unique name/address, auth hashes, sorted proxies and ordered rules (64KiB/max70 proxies, 64 custom names, 64rules). Entry auth hashes need not be distinct at wire level; private core profile can require independent credentials. Node names use node:opaque-ID; group aliases use group:SHA256(local stable group ID), avoiding raw128-byte ID prefix overflow. Mandatory native builtins remain in observation but GLOBAL/COMPATIBLE/PASS cannot be business rule targets. Explicit direct uses a local named Direct node.

Custom remote nodes support the T038 finite profile types Http, Socks5, Shadowsocks, Trojan, Vmess, Vless, Hysteria2 with canonical DNS/IP:port; zones, userinfo, hidden dialer chains and mutable external providers are forbidden. Private connection fields remain in sealed generated config/provider assets; whole configSHA binds them without per-password public hashes.

Business Selector has exactly one declared node/parent-group or explicit REJECT member, Selected equals that member. This implements manual, follow and explicit optional-empty reject groups without first-node defaults. URLTest has only remote leaf candidates, nonempty unique Members, Selected empty, mandatory Probe{url,interval_seconds,timeout_ms,tolerance_ms}; no dynamic selected or measured delay in immutable snapshot. Interval1..86400s, timeout1..60000ms, tolerance0..65534ms. The broader Intent schema does not imply native range support; compiler rejects out-of-profile values instead of truncating uint16. Probe accepted HTTP status is fixed200..299. Probe URL is strict HTTP(S), no userinfo/fragment/invalid endpoint. V1-style static rule order, last Match, target refs and cycles remain fully checked.

## Protected auto selection

Keep stock/native mode unchanged. Each protected URLTest is configured once before core publication with validated immutable probe policy and the actual builtin REJECT proxy. All configured candidates are direct outbound leaf proxies, so an empty native provider fallback cannot reach COMPATIBLE. The protected branch bypasses the native ten-second selection cache and implicit first candidate.

An atomic per-proxy observation keyed by exact URL plus accepted-status policy contains Known, Success, CompletedAt and measured DelayMS. It is published as one mutex-protected value at completion of the real proxy URLTest, only for registered protected policies; Success requires err=nil, context not cancelled, and HTTP status accepted. Successful delay0 is valid; absence and failure are different. Native alive/history calls are insufficient because they are separate reads and zero is ambiguous. Core restart starts with no observation. No persistence or invented sample is added.

Protected selection only considers known successful observations within maxAge=2*interval+timeout; timestamps stripped of monotonic data allow suspend wall-time gaps to expire evidence, and backward-clock negative ages are invalid. Select minimum observed delay within the exact candidates, retain a qualified prior candidate within tolerance using widened arithmetic. This is a bounded probe policy, not proof of best business latency. No qualified candidate returns builtin REJECT, including before first successful probe and after all failures; no direct/other-source/default-first fallback. Selection observes independently updated nodes and does not promise a globally atomic network-quality snapshot.

The registry lock never spans network IO. Group selection lock may read per-node observations, but observation publication never acquires group locks. Enabling a policy is idempotent for the same immutable policy and refuses conflicting reconfiguration. Protected Set/ForceSet cannot override the declared policy. Snapshot reads enumerate members without touch/probe and inspect immutable configured policy; they do not call Now() for URLTest. Actual native healthcheck URL/status/timeout/interval/lazy and tolerance must be checked against declared policy before enabling; echoing supplied policy without that check is insufficient.

## Compiler and integration obligations

Compilation is pure over supplied private validated snapshots, intent, rule assets, binary/capability references and explicit runtime endpoint credentials. Every referenced source (including a pin outside active source) must exist and Snapshot.Validate must pass. Group metadata calculation alone never grants private-material authenticity. Source assets must bind original bytes, source/key/parser/snapshot identity and declared region rules/metadata, so region changes cannot escape the Plan input digest merely because original provider bytes are unchanged. Generated proxy aliases are opaque, never provider names.

Candidate bundle includes canonical intent/generated config, all exact provider/rule input assets, typed route map, independently produced expected v2 snapshot and binary/capability bindings. No asset/network discovery occurs during pure Plan. URLTest probe results are not compile inputs. No empty group/unknown region/pin can acquire fallback. Initial profile retains existing64KiB generated and finite node/rule limits; higher parser limits are not claims of runnable scale. Incomplete rule/entry/compiler branches must return explicit blockers, never a plausible partial bundle.

Only a separately built/hash-pinned new core with actual closed/start/activate/drain/reopen, successful/failed/unprobed auto selection and source/follow routing evidence can enter approved capability lookup. V1 remains supported by its own existing lookup and exact wire. Product controller/launcher/material validation must choose the version from the accepted capability and bind it to the exact binary; a client/core-supplied mode string cannot mint approval. Existing ownership, operation journal and publication order are preserved; any necessary integration change must receive targeted negative/fault tests.

## Evidence required before T041 closure

1. Pure v2 codec and negative cross-version/shape/cycle/probe/static-vs-live tests.
2. Protected atomic probe publication/selection unit and race tests, then real source proxy+HTTP endpoint tests for failed status, timeout, unknown/all failed, cancellation and candidate-only switching. Exact0ms/clock-boundary selection is verified with injected observations; a real loopback test cannot force a zero-duration measurement.
3. New core guard rejects unknown/global/unsafe fields, semantic drift and version confusion; old protected-v1 path still works.
4. Independently projected snapshot equals actual native state while legal automatic choices change without altering immutable snapshot; follow connections track the same auto parent.
5. Full generated candidate/Plan digest binds all references and reaches existing US5 gate, with explicit failure and no partial authority. T043/T044 still own product update/apply integration and complete two-source matrix; they are not done by these codec/core checks.


## Build and admission correction (2026-10-28)

Native direct-exec tests alone do not establish launcher compatibility. The first normal candidate was built with inherited CGO defaults and contains PT_INTERP. The existing pinned-FD launcher correctly rejected it before operation admission or product process creation (product-normal-01). Its initial capability registration was withdrawn; the original registration bytes, binary and failure are retained as evidence. Production approval now additionally requires explicit CGO_ENABLED=0, GOOS=linux, GOARCH=amd64, GOAMD64=v1, no PT_INTERP, successful platform.OpenExecutable on a private single-link copy, and a fresh build matching the tested static binary. The diagnostic race binary necessarily has a separate hash and is not granted a production capability.

V2 BasicMaterial admission also projects the validated generated profile independently of the supplied validation-file bytes and compares the complete canonical snapshot (including Probe, members and entry authentication hashes), before publication/admission. This does not replace the later core-native snapshot and original-process proof. V1 behavior remains under its existing boundary.

The first compiler API is a finite shared-entry implementation: policy.Compile takes strict Intent JSON, authenticated in-memory subscription Snapshots, a declared v2 capability/binary and explicit private endpoint credentials; it performs no IO. It binds full source asset bytes including every local region rule, emits typed route mappings and independent expected snapshot, and returns detached bundle/input views. Apps, GOST, enabled retention, process/application predicates and IPv6 rules remain explicit unsupported errors until their dependent tasks implement them. The bundle grants no launch authority; US5 still selects an approved capability using the complete immutable BinaryReference. Compiler inputs and errors never silently choose another source or a default candidate.
