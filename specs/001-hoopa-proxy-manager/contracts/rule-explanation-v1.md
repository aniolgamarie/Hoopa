# Pure rule explanation v1

Root implementation decision for T049, 2026-10-29. This is a pure diagnostic API, not runtime authority or evidence of applied routing.

`ExplainRules(raw []byte, sources map[config.ID]subscription.Snapshot, facts *RuleFacts) (RuleExplanation, error)` returns owned diagnostic data. Nil facts requests static analysis only; nonnil facts permits the existing hypothetical Evaluate calculation after full local admission. No filesystem, controller, probe, DNS, clock or selection mutation is allowed.

RuleExplanation contains Validation (valid/invalid), Basis (configuration_intent), Evidence (not_observed), Rules in original order, DefaultTarget, optional Blocker, optional Calculation, CalculationBasis (supplied_facts only with a calculation), and ShadowAnalysis (complete/budget_exhausted/not_performed). Each ExplainedRule contains Index, ID, exact intended Target, sorted unique logical Fields, optional ShadowedBy (the original earlier index), and ShadowProof (duplicate/conjunction_subset/not_proven). RuleBlocker contains only fixed Reason and logical Field. Reports do not expose predicate literals, facts, provider data, paths, probe URLs, credentials, run identity, selected auto node, health or latency. Aggregate formatting is a private constant; explicit logical IDs/targets are intentional output.

Malformed declarations return zero report and ErrRules. Strict Draft-valid declarations whose Apply references or authenticated source/target admission fail return Validation=invalid with one deterministic blocker, nil error and no Calculation/shadow proof. This means diagnostic analysis succeeded, never that the configuration is admissible. NewRuleSet keeps its existing zero/ErrRules behavior. Invalid supplied facts used by a valid admitted evaluation return zero report/ErrRules; malformed facts on unevaluated later rules remain unused. A small private admission helper shared with NewRuleSet may expose safe fixed diagnostics, but no partially admitted RuleSet may escape. Snapshot.Validate must precede metadata-based target resolution; unused sources are not dependencies. All targets, including shadowed and default, remain validated.

Static shadow proof is deliberately limited to semantic duplicates and exact normalized-atom conjunction inclusion: an earlier conjunction atom set that is a subset of a later set proves the later rule cannot be the first decisive rule for well-formed facts. Domain normalization uses the evaluator's ASCII case/single trailing dot rule; CIDRs use parsed masked prefixes; app/process equality stays exact. No general suffix/subnet containment, contradiction solving, union coverage, DNS or process inference is included. ShadowedBy selects the first earlier proving rule. not_proven is not a claim of reachability. An annotation never skips validation or changes evaluation.

Bound optional proof work to 4096 rule-pair comparisons and 65536 atom visits/comparisons across normalization and subset checks, with no input-dependent unbounded quadratic search. On budget exhaustion retain the complete rule listing/admission/calculation, leave remaining relationships not_proven, and report budget_exhausted. Invalid admission reports not_performed. These limits are analysis limits, not runtime route or compiler capability limits.

Actual connection evidence remains not_observed even when hypothetical supplied facts produce a definite target. Pure process predicates can be calculated from supplied facts without granting the current core their observation or compilation capability. Installed app bindings, runtime reachability and connection/rollback impacts belong to the control layer and later T050.
