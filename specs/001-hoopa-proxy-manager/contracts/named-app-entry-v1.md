## Explicit immutable local bindings

Each managed app has a separate private, immutable entry-binding input. It is independent of the applied bundle: explicit setup can prepare a new binding while an existing generation is running, but setup never opens a port, updates active, reloads the core or changes a Launch. Pure Plan only reads existing bindings. Missing inputs are an explicit failure, never permission to allocate a new port or credential.

The control interface is:

```go
func NewAppEntryBinding(appID config.ID, entry sourceprofile.Entry,
    settings SourceSettings) (AppEntryBinding, error)
func (c *Coordinator) InitializeAppEntry(ctx context.Context,
    expected config.Revision, binding AppEntryBinding) (string, error)
```

Initialization returns the binding digest after the existing private-file durability barrier. Identical bytes are an idempotent retry; different bytes for the same app ID are a conflict. Construction is pure, validates the app ID and settings identity, owns its inputs, and redacts all standard formatting. The entry name is generated as `app:` plus the hexadecimal SHA-256 of the app ID; a supplied empty Name is filled with this name, while a different nonempty Name is rejected. This name does not encode a PID or prove which process used the entry. `policy.AppEntryAlias(config.ID) string` exposes the same deterministic mapping to compilation.

The exact private JSON record has schema_version=1, app_id, source_settings_sha256 and entry. It uses the existing bounded private credential conventions (maximum 16 KiB, exact canonical writer bytes, no unknown/duplicate fields). Storage is `state/credentials/app-entry-<SHA256(appID)>.json`, under the existing Store writer ownership. Read does not create directories or repair. Publish uses the existing exclusive-stage/file-fsync/rename/parent-fsync pattern and refuses replacement. An uncertain write does not become a reported successful setup; an identical retry must re-establish durability. This is explicit local-input initialization, like SourceSettings initialization, not a runtime operation or a second Apply journal.

The coordinator holds its existing writer boundary for expected-revision, current settings and binding-uniqueness checks and publication. Bindings are tied to the exact existing source settings digest. Names, endpoint pairs and credentials cannot collide with the controller/shared entry or another retained app binding, including bindings not selected by the candidate Intent. No query regenerates a missing record. Initialization of a missing record must refuse if a verified retained bundle references that app's prior binding; missing/corrupt provenance requires recovery rather than silently rebinding. Losing settings while app bindings remain similarly cannot authorize a new installation identity. An orphan prepared binding is harmless local input; it cannot start traffic without a later complete confirmed Apply. Deliberate erasure of all independent history by the same OS user is outside this detection claim, as with the existing source-settings boundary.

Absence/uniqueness checks need exhaustive retained-input evidence, not merely the active bundle or visible Journal generations. Add descriptor-relative, bounded Store inventory readers using the same verified private directory/file handles as existing Store reads. Enumerate incrementally, cap the initial profile at 1,024 app binding records (including distinct identities retained in history) and 4,096 retained bundle directories, and validate every relevant record/manifest before returning a complete result. Exceeding a bound or encountering corrupt/unreadable provenance fails without a partial inventory, new binding or automatic cleanup. An arbitrary bare filesystem path walk is not an authority boundary. Bundle contents need not all be retained in memory together; reuse per-bundle integrity checks sequentially. The credentials directory scan also caps all visited entries, including unrelated prepared inputs, at 4,096 so irrelevant names cannot make setup work unbounded. A staged or unreadable bundle is not treated as absent history. These are finite setup limits, not permission to discard old leases or evidence.

The explicit local initializer is initially a control primitive for the routing tests and later onboarding CLI. This contract does not claim that a public app-creation CLI/API has shipped. Cleanup/migration/reassignment of retained bindings is not an implicit side effect of initialization, Plan, status or doctor.

## Complete compilation and Plan identity

`policy.RuntimeInput` gains an owned `AppEntries map[config.ID]sourceprofile.Entry`. SourceSettings.Runtime still supplies only the existing shared entry; the coordinator captures separately verified app bindings and populates this map for compilation. The complete binding bytes/digest, source settings identity and app ID must be represented in the Plan input set and generation commitment. Apply re-reads and compares the same local identities before any workdir preparation or runtime effect. A stale or removed binding fails; it cannot silently refresh the approved Plan.

The compiler input must also carry the captured canonical binding material and its parent settings identity. Compilation independently checks that the decoded binding app ID/entry matches AppEntries, that the settings identity matches the supplied parent, and that the exact record bytes produce the declared input digest. An unverified caller-supplied digest beside a mutable Entry is insufficient: changing an entry while preserving that digest must not produce different core bytes under the same generation. The private codec is shared by initialization, capture and compilation so each boundary uses the same byte commitment; no public Plan embeds the credentials.

Only managed, unmetered apps receive entries in this P1 profile. Metered inputs remain unsupported until their dedicated phase. Direct/inherit metadata may remain in Intent without listener allocation. An app predicate referencing a non-managed profile cannot pretend that it receives a managed ingress context; compilation rejects that unsupported route. The approved profile's existing maximum of four total listeners includes the shared entry, so excess managed entries are an explicit capability failure. Process instance/name/path conditions remain unsupported by this profile.

Compile includes the shared listener and every declared managed, unmetered app entry, sorted by app ID for deterministic output. A managed app without an app-specific rule still needs its binding and uses the ordinary ordered rules/default; it cannot silently share another app's entry. It lowers each app predicate to the exact generated IN-NAME atom in the original ordered rule sequence, including all with domain/IP conditions. It must not set a listener-level proxy override or add an implicit app-priority route. Every app/group/node/default reference is checked before the full candidate is published. The route metadata retains app-ID-to-entry mapping separately from node/source/group references and never exposes credentials in normal projections.

An input binding never changes an already applied core. Explicit P1 Apply still performs complete start/replace with interruption disclosed and confirmed, using the existing US5 state machine, closed-start checks, all-entry verification, original process identities and complete rollback. Retained old-launch/entry leases and metering transitions belong to their later tasks; these routing tests do not claim automatic connection migration or reclaim unknown leases.

## T046 executable test obligations

Define two managed unmetered apps with distinct bound ports/credentials, two stable groups and one exact source/node pin. Preparation uses actual local binding primitives; runtime uses complete compilation and the existing product Plan/Apply path. Missing binding, digest changes, duplicate endpoint/credentials and unsupported process predicates must fail before runtime mutation. Check actual app, domain and IP ordered selection, fixed pin identity, and explicit rejection with no silent node/source/direct fallback. Pure rule truth-table results are not an actual path witness.

Hold an application connection, replace the full candidate, and verify the previewed interrupt behavior separately from new-connection routing. Occupy a later candidate listener so partial multi-entry binding cannot be accepted as success; prove candidate exit, full old-entry restoration and original identity/ownership protection without killing the foreign listener. Kill the real management process while both already applied app entries carry traffic, observe held/new behavior separately, and reopen without creating a duplicate core. No GOST or SQLite dependency may be needed for these cases.

Tests may use an explicitly scoped integration build tag and remain red until T047/T048/T050 are implemented. The test-definition milestone requires valid syntax and a requirement-to-assertion map, not fake passing fixtures. Actual Linux acceptance is T051; no other platform, original-process identity or complete product support is inferred here.

## Implementation input commitments

The shared pure codec is config.AppBinding, constructed/decoded independently of the actual settings installation. Its private canonical bytes are the commitment; only the coordinator's constructor and capture prove the real parent settings and cross-entry uniqueness. The complete compiler input adds AppBindings map[config.ID][]byte and SourceSettingsSHA256 string alongside RuntimeInput.AppEntries. For each supported managed app, compilation must independently decode exact canonical bytes, compare app ID/entry/parent digest, and include one app_binding input plus identically named private bundle asset (app-entry-<SHA256 app ID>.json). Extra undeclared/non-managed binding or entry inputs are rejected, not silently omitted. No public Plan exposes these bytes.

The app-core profile uses compiler version hoopa.apps.v1, while basic-sources keeps hoopa.sources.v1 and its existing no-app output bytes. Generation construction uses the compiler version from the preliminary complete compilation, its full sorted input set and exact settings digest. The existing source-generation.v1 commitment envelope can remain unchanged. A route map adds app-ID-to-entry records only when nonempty, without credentials.

Explicit initialization validates all retained bindings against current settings and compares the complete endpoint/name/auth-pair set under the coordinator lock. A missing or mismatched live record that is referenced by any retained bundle is a recovery requirement for this initialization operation, not permission to republish or regenerate it. Existing forwarding and read-only diagnostics are not repaired as a side effect.

Pure app compilation preserves bypass as child-access metadata in the canonical Intent. It neither inserts bypass routing rules nor implements NO_PROXY itself; child environment behavior remains the later access stage. SourceSettings v1 continues to encode only the shared/controller inputs and rejects a nonempty RuntimeInput.AppEntries map rather than silently discarding it.

App-bearing Plan capture reuses the coordinator inventory/history validation under its existing writer lock. It validates all retained inputs, including unused bindings, then owns only declared managed/unmetered canonical records. Missing history counterparts require recovery; missing never-used records are unavailable. An Intent with no managed/unmetered entry does not consume the app inventory. Apply performs the same fresh capture before material/workdir publication, using the existing source Apply admission sequence.
