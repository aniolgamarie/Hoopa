# 终态运行目标的恢复接纳前核验 v1

2026-10-27，T034 的 F14 准备修订。已存在的归属冲突必须在任何新恢复记录或临时残留
维护之前拒绝；完整矩阵仍须实际执行。本契约不把查询变为恢复，也不增加编译能力。

相同已接纳请求仍最先精确重放；不同内容复用 ID 拒绝。新请求先核对参数、revision、
目标及其他未终结调用关系，然后对以下目标执行只读预检：

- 严格证据可解码的 committed/rolled_back config.apply 所对应的当前已运行原实例。
- 严格证据可解码的 committed runtime.start，包括普通启动、单次重启和已运行接管。

预检复用原核验器的终态只读分支，在同一 Coordinator 控制锁内进行，传入空 boundary。
这些终态分支不得 Advance、PublishActive、补登记、activate 或发送信号。
当前实例不成立时返回 CONFLICT，created=false，不维护临时记录，也不接纳新的恢复 ID。
取消/超时和写入不确定性仍保留其原错误分类。拒绝后的同一未接纳请求，可在输入原件
实际恢复、全部前置条件重新满足后重新提交；它尚未取得持久去重身份。

预检通过后才允许既有显式维护及新恢复调用的持久接纳；随后执行原恢复流程并再次
核验。预检不是跨时间授权票据。如果身份只在接纳后才变化，调用已发生，按既有语义
保留 pending/degraded 结果，不能改报成没有任何效果。

pending 原目标继续既有显式恢复流程；无法严格解码的终态证据继续原诊断流程，不
补造原件。runtime.stop、service.stop 的历史事实不要求存在活核心。RolledBack
runtime.start 不属于受支持的活核预检目标，保留原诊断行为。

本次改变没有把 F14 的零变化断言删掉；新增受限回归先证明旧顺序会接纳失败调用，
再证明前置冲突零变化，以及接纳后的变化确实保留诊断。实际补验只覆盖原注册文件
缺失这一条相关路径，不宣称所有 PID 复用/外部 listener/缺 nonce 场景已验收。
