# Local application dispatch implementation boundary

Root decision, T056, 2026-10-29. This supplements the launch/store/record contracts; implementation and component tests alone do not complete actual CLI acceptance.

The fixed self launcher takes no sensitive command-line arguments. Anonymous inherited pipes at child descriptors 3/4/5 carry payload, authorization and finite status. They must be separate FIFOs with the expected read/write access and are marked close-on-exec. Payload is `HLPAY001`, big-endian 32-bit argv count and length-prefixed raw byte strings, followed by the same environment vector. Limits are 2 MiB total, 4096 entries per vector and 131071 bytes per string; NUL is forbidden, invalid UTF-8 is retained, argv[0] is nonempty, and trailing data is rejected. Payload writer EOF completes framing; no payload file is created.

After decoding, the helper sends one `R` byte. It executes only after exactly one `G` byte followed by EOF on the authorization pipe. Parent EOF, invalid framing or absent authorization cannot execute user code. The helper reports a protocol failure with `P`, or an exec/search failure with `E` plus a finite byte: 1 format, 2 not found, 3 permission, 4 unavailable. Status is closed by successful exec; EOF alone never proves that application main ran. Child root identity and authorization intent must be durably recorded before sending G. No historical record can mint a spawn ticket.

All three user stdio descriptors are duplicated with close-on-exec before creating any control pipes; failure rejects before reservation. Go receives actual files, without stream-copy goroutines. Each wrapper supports one active Run in its process; independent wrappers may launch concurrently. Parent argv/environment are copied into bounded anonymous payload and are never placed in the helper's argv, ambient environment or durable history.

Product integration refinement: the helper starts in its own process group without Go's immediate Foreground transfer. After receiving ready, retaining the original clone pidfd and writing birth, the wrapper checks the same controlling terminal/session/prior foreground and exact original child, then transfers foreground while the helper still waits for GO. Only then is authorization recorded. This supersedes the earlier immediate Go Foreground wording for the product runner; the component spike's result remains historical. Start failure or a missing clone pidfd therefore leaves foreground untouched. Any attempted handoff is restored only while the original child remains unreaped, with the same mask/session/identity protections. This retains the cooperative-session, no atomic foreground CAS limitation.

An argv[0] containing `/` is passed directly to execve. Otherwise the helper searches the first exact `PATH=` entry in the captured environment. Absent PATH means not found; empty PATH components explicitly name the current directory. Each candidate is attempted with execve, preserving the original argv[0]. ENOENT/ENOTDIR advance, EACCES is remembered, and ENOEXEC never invokes a shell. These finite exec/search failures do not turn an ordinary application exit126/127 into a launcher failure.

Setup is bounded by a ten-second context before authorization. Cancellation/failed preparation closes the gate and may SIGKILL only the original un-dispatched helper through its original clone-created pidfd. Once authorization is durable, context cancellation never silently kills an authorized application or abandons its wait. Wrapper-directed INT/TERM/HUP/QUIT still forward to that original direct child. After dispatch, observe original pidfd exit without reaping, restore TTY while the exact child remains zombie, perform the sole Cmd.Wait, stop signal forwarding, then close pidfd. Terminal metadata is attempted using a separate bookkeeping context even if the original setup context expired. A wait/restore/record failure returns finite wrapper failure with any actually observed exit retained; it does not report application success.

Configuration capture and live qualification are separate. Read-only capture prefers committed bundle, never falls back to draft when committed evidence is invalid, and verifies selected managed entry against the generated profile, retained binding and parent settings. Direct/inherit require no runtime credentials or service. Managed qualification consumes freshly authenticated management status and independently observes the original core, full controller identity, open gate and exact entry socket owner before SOCKS password authentication without a destination CONNECT. It rechecks active identity afterwards. No service start, reload, listener allocation or connection migration occurs. A later explicit Apply can interrupt service; this is not an atomic transaction against future Apply.

Here, missing history means missing selected committed originals or the initialized launch-history namespace/identity marker. Run allocates no binding and does not rescan all other retained bundles. The exhaustive binding inventory and continuity check in named-app-entry-v1 remains required for initialization, Plan and Apply, which can introduce or change binding use. Consuming an already committed exact entry does not assert that unrelated retained bundles were re-audited. A missing/mismatched selected live binding still refuses, even if its old bytes remain in a bundle.
