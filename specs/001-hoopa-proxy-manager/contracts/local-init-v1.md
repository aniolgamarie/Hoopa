# Explicit local initialization v1

T054 contract, Linux/amd64 implementation scope. `hoopa init --mihomo PATH [--gost PATH] [--input PATH] [--controller-port N --shared-port N] [--app-port APP=PORT ...]` prepares local input only. It never downloads or executes a dependency, opens a listener, starts a service/core, applies a generation, changes proxy environment, or creates a traffic ledger. Existing explicit T033 control-only empty-Store bootstrap remains supported. `run` and queries never initialize missing state.

`control.PrepareInitInput(InitOptions) (InitInput,error)` is pure and owns copied input. Explicit binary paths must be absolute, clean, nonempty (Mihomo required), bounded at4096 bytes and contain no NUL. Input is optional strict canonicalizable JSON bounded by `MaxRequestBytes`; the CLI's existing bounded JSON/YAML reader converts a supplied document. No input returns incomplete with missing `intent`; absent/empty declared binary `version`/`sha256` produces corresponding finite missing names (`mihomo_version`, `mihomo_sha256`, `gost_version`, `gost_sha256`). Such a report does not declare the remaining document valid and performs no filesystem writes. Invalid JSON, unknown/malformed complete input or conflicting explicit/declared binary paths is INVALID_ARGUMENT. Complete input must pass existing `config.ParseIntent(IntentDraft)` unchanged. Supplying --gost requires an agreeing declared Gost reference; an omitted flag does not remove an existing declared reference. No metadata placeholders or guessed versions are persisted.

Ports are explicit integers1–65535; omitted options are zero. Controller/shared must be supplied together or both omitted. All supplied ports must differ. App keys must parse as IDs, occur in the complete input as managed/unmetered apps, and be unique (the CLI rejects repeated keys). Invalid/incomplete declarations never authorize port allocation. Existing immutable settings/bindings are reused; explicit differences conflict. A missing settings pair or managed app binding remains a finite missing-input result. Metered apps remain unsupported and are reported; init does not silently disable metering. No port availability or future connectivity is asserted.

`control.InitializeLocal(ctx,paths,options) (InitReport,error)` performs pure validation before opening any writer, inspects dependencies read-only, and returns an incomplete report without creating state. Complete declarations may prepare a canonical protected draft, the launch-history namespace, and optional source settings/app bindings. Dependency absence or hash mismatch is reported and does not make direct/inherit draft preparation impossible. Inspection never executes `--version`; declared version is not a verified runtime capability. Report dependency states are `available`, `unavailable`, `mismatch`; reasons are `hash_matched`, `not_readable`, `not_regular`, `too_large`, `hash_mismatch`. Inspection is bounded at128 MiB per file and cancellation-aware. A matching hash proves those observed bytes only.

`state/draft-input-v1.json` is a private canonical envelope with `schema_version:1`, `intent_sha256`, and `intent` containing canonical complete Intent JSON. The Store writer validates old evidence before replacement and atomically publishes/syncs new bytes. It does not advance active revision, generation or desired runtime. Run can later read this declared draft for direct/inherit; it is never managed runtime authority. Draft history is not retained here: launch reservations must capture their own immutable app/profile commitments. Runtime path overlap with this record and `app-launches` is rejected. Launch namespace installation obeys [application-launch-store-v1.md](application-launch-store-v1.md); ordinary Store opens do not install or repair it.

Existing draft and launch-history metadata are checked read-only before publishing any new settings/binding. Known settings/binding conflicts are checked before draft publication. Local preparation is not an all-or-nothing runtime Apply: earlier immutable preparation may persist when a later filesystem write fails. This allowance does not authorize publishing new credentials before detecting pre-existing history corruption. Errors remain bounded and the next explicit identical init revalidates and reuses persisted material. Sync uncertainty poisons the current writer and stops subsequent mutation. No cleanup, regenerated credentials, automatic service stop, replay-as-start or false rollback is permitted. The active service's writer lock causes an explicit conflict.

Successful output uses the existing v1 JSON envelope with `request_id:null` and an `InitReport`; this is a local command, not a new management RPC. Arrays are always arrays. `input_state` is `incomplete` or `complete`; `prepared` means the draft and launch namespace were durably prepared, not runtime readiness. `prepared_components` contains only `store`, `launch_history`, `source_settings`, `app_entries`, `draft`. `missing` contains the input names above and/or `source_settings`, `app_entries`, `metering_backend`; `missing_app_ids` identifies managed apps without prepared unmetered bindings or with unsupported metering. `app_entries_ready` counts bindings for this declaration. `next_steps` is drawn from `provide_complete_intent`, `provide_source_ports`, `provide_app_ports`, `metering_not_supported`, `plan_and_apply`. No paths, credentials, complete argv/environment or raw errors enter this report. Reports about prepared settings are not evidence of a listener or process identity.
